This topic provides guidelines for writing AI Descriptions for custom objects, such as record types, transaction types, and fields. For general information about the AI Description field, see [AI Description for Custom Object Definitions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0109014837.html).

Use the dos and don'ts outlined in the following table to help you write your AI description.

| Do | Don't |
| --- | --- |
| 
-   Include what the custom record, field, or transaction is used for, and list the types of data it holds.
-   Explain how the object fits into your business process.
-   Focus on the business reason or why this custom object exists.
-   Highlight relationships to other records or fields if they're essential for understanding.
-   List the types of data the field holds (if describing a field).
-   Keep your description short and focused (maximum 280 characters, including spaces).
-   Use clear, everyday language.
-   Describe the purpose and meaning of the custom object in language that someone outside your organization could understand.
-   Update the description if the business use changes.

 | 

-   Use internal jargon, codes, or technical abbreviations.
-   Reference NetSuite screen names, menu paths, or navigation steps.
-   Include internal IDs or irrelevant numbers.
-   Copy and paste unrelated documentation or code.
-   Use special formatting, bullet points, or non-standard characters.
-   Exceed the 280-character limit.
-   Add specific examples or user instructions-keep it general and descriptive.
-   Use the AI Description field to provide instructions rather than describe the custom object

 |
