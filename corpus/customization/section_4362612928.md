A custom record type can be set up to permit users to define hierarchies among values for that custom record type. Note that this hierarchy applies to the relationships between individual instances of the same custom record type, rather than between different custom record types themselves.

For example, a custom record type has been created to store employee information. You can set up hierarchies between instances of this record type to indicate supervisory relationships.

First you must set up the custom record type with the Hierarchy option enabled.

![Sample Custom Record Type with Hierarchy box highlighted.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteBuilderCustomization/HierCustRecTypeOption.png)

When the hierarchy functionality is enabled on the custom record type definition page, you can define a parent-child hierarchy between two record instances of the same type. You can define this hierarchy either on the parent record or on the child records.

On a parent record instance, you can click **New Custom Employee** on the Child Records subtab to create a child record.

![Sample Custom Employee record with New Custom Employee button highlighted.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteBuilderCustomization/HierCustRecFromParent.png)

On a child record instance, you can select the parent record from the list, or create a new record instance to be the parent.

![Sample Custom Employee record displaying Parent list.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteBuilderCustomization/HierCustRecFromChild.png)

The Custom Record List page shows the hierarchy for the records in the format <parent record>:<child record>.

![Custom Employee List showing parent record : child record format.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteBuilderCustomization/HierCustRecList.png)

Important:

Although this example illustrates only two levels of hierarchy, this feature supports multiple levels of hierarchy among custom record instances.
