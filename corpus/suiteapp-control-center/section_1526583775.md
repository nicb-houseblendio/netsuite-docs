Each version of your SuiteApp is a version composed of a SuiteApp ZIP archive. The archive contains a SuiteApp project representing the SuiteApp. For information about SuiteApp projects, see [SuiteApp Projects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1509931104.html).

For information about creating the SuiteApp ZIP archive, see [Managing SuiteCloud Projects as Compressed Files in SuiteCloud IDE Plug-in for WebStorm](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_159709033768.html).

To be valid for SuiteApp Control Center, your SuiteApp ZIP archive must meet the following criteria:

-   The ZIP is a valid archive.
    
-   The ZIP contains a manifest.xml file.
    
-   The manifest element in manifest.xml file has the projecttype attribute value set to SUITEAPP.
    
-   The projectid field exists in manifest.xml, and its value matches the Project ID value set for the SuiteApp in SuiteApp Control Center. For information, see [Properties of a SuiteApp Project](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1509931104.html#subsect_1520876235) and [Creating a SuiteApp Definition](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1526316405.html).
    
-   The publisherid field exists in manifest.xml, and its value matches the Publisher ID value defined for the SuiteApp in SuiteApp Control Center. For information, see [Properties of a SuiteApp Project](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1509931104.html#subsect_1520876235) and [Creating a SuiteApp Definition](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1526316405.html).
    
-   The manifest.xml file has a projectversion field value that's higher than the version number of either the leading release version or lagging release version. A new version can't use the same project version number as an existing version, but you can reuse a version number from a deleted version.
    
-   The manifest.xml file has a valid projectversion field value. The value must use semantic versioning. For example, if the project version is 1.02 with a minor revision 01242017, the project version is 1.02.01242017.
    
-   The manifest.xml file contains a projectname field value.
    

Important:

Even though locking preferences (locking.xml) and hiding preferences (hiding.xml) aren't part of SuiteApp ZIP validation, you still need to set them up in the SuiteApp project for the installation to work. These preferences are only required for SuiteApps defined in SuiteApp Control Center. For information about configuring those preferences, see [Setting Installation Preferences in SuiteCloud IDE Plug-in for WebStorm](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1530903069.html).

#### To create a SuiteApp version:

1.  Go to Control Center > My SuiteApps > My SuiteApps.
    
2.  Do one of the following:
    
    -   For a SuiteApp, click ![SCC ellipsis button](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteAppControlCenter/SCCEllipsisButton.png) and select **Manage Versions**.
        
    -   Click the SuiteApp name to view its details, then click the **Versions** tab.
        
3.  Click **Create New**. The New SuiteApp Version popup window appears.
    
4.  Click **Choose file** and select a SuiteApp ZIP archive from a local directory or network share. NetSuite File Cabinet files can't be selected. After you upload the SuiteApp ZIP archive, the **Project Version** field is populated with the value from the projectversion field in the manifest of the SuiteApp project contained in the ZIP. That value becomes the version number, for example, 1.0.1.
    
5.  Specify the following options:
    
    -   **Phase** - is the SuiteApp version phase, which can be Leading or Lagging. For information about those phases, see [SuiteApp Version Phases](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_1526582725.html#subsect_1537984829).
        
        You can also change this option when editing the SuiteApp version, if the version is in the Pending state.
        
    -   **Minimal Required NetSuite Version** - is the minimum NetSuite version required for the install base to install this version of the SuiteApp.
        
6.  Click **Create**. The new version is added to the Version History list, and you'll see a confirmation that the version was saved.
    
    For information about the version fields and actions you can take, see [Viewing the SuiteApp Version History](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1526584029.html).
    
7.  (Optional) Click **Done** to close the SuiteApp details and go back to the My SuiteApps page.
