On the Permissions subtab of the Work-Related Costs Configuration page, you can assign certain roles the permissions to view and configure the Netherlands Work-Related Costs report. You can also restrict the capability to edit the **WKR Category (NLD)** field on a transaction to specific roles.

Note:

Because the Work-Related Costs report can only be generated for a subsidiary with EUR as base currency, the employees you assign WKR reporting permissions must have access to this subsidiary. For more information, see [Assigning a Subsidiary to an Employee](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_N276604.html).

You can also manage these permissions in their respective custom records:

-   For permissions to access the WKR-related pages, you can edit the **NL WKR Report Access** record at _Customization > Lists, Records & Fields > Record Types_.
    
    On the Permissions subtab of this custom record, you can specify the roles and their permissions. Refer to the following permission levels and their corresponding capabilities:
    
    | Permission | Permission Level |
    | --- | --- |
    | 
    -   Access to the Work-Related Costs Report page and the Work-Related Costs Configuration page
    -   Capability to configure the report.
    
     | Edit |
    | Access to the Work-Related Costs Report page | View |
    
-   For the permission to edit the WKR category on the transaction record, you can edit the **WKR Category (NLD)** transaction line field record at _Customization > Lists, Records & Fields > Transaction Line Fields_.
    
    On the Access subtab, you can specify the roles to whom you want to grant permissions, and add the access level **Edit**.
    
    Note:
    
    To edit the **WKR Category (NLD)** transaction line field record, your logged-in role must have the Custom Transaction Fields permission.
    
    Administrators can grant this permission to a user at _Setup > Users/Roles > User Management > Manage Roles_. On the Setup subtab under the Permissions subtab, the role must have the **Custom Transaction Fields** permission and a level of **Edit** or **Full**
