You need to create a JavaScript file with your Custom GL Lines plug-in implementation's business logic. You can use the SuiteCloud IDE, or another JavaScript IDE or text editor.

The following table describes the functions and objects available in a Custom GL Lines plug-in implementation script file:

| Function / Interface Object | Description |
| --- | --- |
| [customizeGlImpact(context)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8102434206.html) | You must create an implementation of this function in the plug-in implementation script file. The script file can contain other helper functions. NetSuite runs this function when you save a transaction of the type and subsidiary you set for the plug-in implementation. NetSuite runs this function one time for the primary accounting book. If you use Multi-Book Accounting, this function also runs for each secondary accounting book that you set up for the plug-in implementation. |
| [StandardLines](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_48095106414.html) | Contains an array of all standard lines with GL impact in a transaction as StandardLine objects. Use the methods available to this object to access properties of individual standard lines with GL impact on a transaction. |
| [CustomLines](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_7095141731.html) | Contains an array of all custom lines with GL impact in a transaction as CustomLine objects. Use the methods available to this object to add and modify custom lines with GL impact on a transaction. |
| [AccountingBook](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_74095018462.html) | Represents the accounting book passed to a Custom GL plug-in implementation when you save a transaction. Use the methods available to the book object to determine if it's a primary or secondary book. Or, you can get the internal NetSuite ID of the accounting book. |
| [ReadOnlyTransactionRecord](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_42095041987.html) | Use this to access properties of the transaction with SuiteScript API nlobjRecord functions. You cannot modify the transaction. When you create a new transaction in synchronous mode, the record ID is not available. |

For more information, see the [Custom GL Lines Plug-in Process Flow](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4211909641.html) and [Custom GL Lines Plug-in Implementation Object Model for SuiteScript 2.x](#bridgehead_19124609924).

## Rules and Guidelines {#bridgehead_66122927922}

Use the following rules and guidelines when creating the plug-in implementation script file:

-   The plug-in script file can have any name, provided it has an implementation of the interface function.
    
-   You can create utility files with helper functions for the main implementation file. Include the files when you create the plug-in implementation for the Custom GL Lines plug-in in NetSuite. For more information about utility files, see [Utility Files for a Custom GL Lines Plug-In Implementation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4224037854.html).
    
-   You can use a custom record type to store references to the required NetSuite standard records. See [Using a Custom Record to Reference Internal NetSuite IDs Example](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4224038929.html).
    
-   You can use SuiteScript API modules in a plug-in implementation, for example, the [N/record Module](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267255811.html) and [N/query Module](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1510275060.html). For more information, see [SuiteScript 2.x API Reference](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_4140956840.html). However, using these APIs may slow down your plug-in implementation, so use them only when needed to optimize the performance of the plug-in implementation. In general, searching for records yields better performance than loading NetSuite records.
    
    These functions also have governance limits. The plug-in script file lets you use up to 1000 usage units with SuiteScript. For more information, see [SuiteScript 2.1 API Governance](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157072844224.html).
    

Important:

For additional guidelines and best practices, see [Custom GL Lines Plug-in Guidelines and Best Practices](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4229148151.html).
