Important:

The Financial Institution Connectivity Plug-in interface uses SuiteScript 2.0. Your entry point scripts and supporting library scripts must also use SuiteScript 2.0. For information, see [SuiteScript 2.1 Script Creation Process](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4417248719.html) and [SuiteScript 2.x](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8161516336.html).

Use a Financial Institution Connectivity Plug-in to directly connect to financial institutions and automatically receive inbound transmissions through NetSuite, daily. Inbound transmission enables you to automate cash balance reporting and schedule account statement downloads.

To create a Financial Institution Connectivity Plug-in, you need to create the plug-in implementation script file, and then upload the script file and other utility files as required. For details, see [Creating a Financial Institution Connectivity Plug-in Script File](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157851408518.html).

You can define alternative implementations that suit your needs by customizing the core plug-in logic. To accommodate this process, NetSuite provides an interface definition that describes the name, parameters, and return type of each function defined in the plug-in's interface. For details, see [Financial Institution Connectivity Plug-in Interface Definition](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_157833142874.html).

To run the plug-in, you must configure and save a format profile that uses the plug-in. The plug-in works with a parser plug-in to enable you to securely connect to a financial institution to retrieve financial data.

Note:

There may be cases where a Financial Institution Connectivity Plug-in requires user credentials for a financial institution. NetSuite itself doesn't ask for or store these credentials, but it lets the plug-in save them securely. This can be handled by a third-party service or a customization for the plug-in.

When a Financial Institution Connectivity Plug-in works with a Bank Statement Parser Plug-in, you're able to import bank data for reconciliation. When a Financial Institution Connectivity Plug-in works with a Financial Institution Parser Plug-in, you can import additional data types, including corporate card charges for expense reporting.

For more information about running a Financial Institution Connectivity Plug-in, see [Conditions for Running a Financial Institution Connectivity Plug-in](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157851439658.html). For testing details, see [Conditions for Testing a Financial Institution Connectivity Plug-in](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157851438706.html).

For details about configuring format profiles, see [Format Profile Creation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_159061330646.html).

A Financial Institution Connectivity Plug-in is also supported by the SuiteCloud Development Framework (SDF). SDF enables you to customize your NetSuite account from an integrated development environment (IDE) on your local computer. For details, see [SuiteCloud Development Framework](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4702622163.html).

In SDF, you can customize a Financial Institution Connectivity Plug-in by defining ficonnectivityplugin objects. For details, see [Financial Institution Connectivity Plug-ins as XML Definitions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_158413297165.html).

After the administrator performs the necessary one-time setup on a format profile record, the NetSuite user can continue with other stages of the Cash Management workflow. These include transaction matching, reconciliation, and corporate card expense reporting. For details, see [Bank Data Matching and Reconciliation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4842302228.html) and [Corporate Card Expenses](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1531259544.html).

Note:

This section only covers the development and administration of a Financial Institution Connectivity Plug-in. For details on using a Financial Institution Connectivity Plug-in to import bank data, see [Automating Imports for Bank Reconciliation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157895120878.html).
