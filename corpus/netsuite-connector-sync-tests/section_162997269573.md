To test order and fulfillment sync, you will need one or more test orders.

You'll retrieve the test orders from your marketplace or cart and manually post them to NetSuite to test the sync.

Before preparing your test orders, make sure you meet these prerequisites:

-   The test order contains tax.
    
    You can ignore this if you're not required to collect tax in any jurisdictions or you sell only on marketplaces that remit tax on your behalf.
    
-   Your test order customer shouldn't already exist in NetSuite.
    
    If you're using a designated customer record in NetSuite, you can skip this step.
    
    For more information about designating a customer, see [Assigning a Fixed Customer to All Orders in NetSuite Connector](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_162687206965.html).
    
-   Make sure all items in your test order exist in NetSuite with matching SKUs.
    
    By default, NetSuite Connector uses the Item Name/Number field as the SKU field on your item records. Also, these items must have quantity available at one or more locations in NetSuite so the test order can be fulfilled.
    

NetSuite Connector can use the same test orders to confirm that refund sync between NetSuite and your marketplace or cart works as expected. If you will be setting up refund sync, you should refund the test order after it has been fulfilled and billed.

For information about how to create a test order for a specific marketplace or cart, see [Creating Test Orders in Marketplace or Cart](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_164354857158.html).
