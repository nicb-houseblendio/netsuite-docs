When you choose a Column field to transform your report into a matrix, you should have a general idea of how many columns will be added based on the field you select. If there are too many columns, the report might not load. To avoid this, try one of the following options:

Note:

Scheduled reports sent as Excel files may be sent successfully regardless of the number of columns. However it's still good practice to minimize the number of columns in a matrix to avoid performance issues when viewing the report in NetSuite.

-   If you know the field you select will add a lot of columns, add it as a column in the report builder instead. This way, each dimension value shows as a row in a single column. For more information, see [Adding Report Columns](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_N738784.html).
    
-   After you select a Column field, click More in the report footer options and manually select only some of the dimensions as columns. Run the report, export the partial results, then repeat the process for the next set of columns and merge the results.
    
-   If you add a persistent matrix column to a custom financial statement, select a (Hierarchy) option in the View Columns By list. This limits the number of unique columns per dimension. For more information, see [Adding Persistent Matrix Columns to Financial Statements](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2109761.html).
