Before you start cloning a NetSuite Cloud EPM environment, you must complete the following prerequisites.

**Source environment:**

-   Let users know that they shouldn't sign in to the source environment while cloning is happening.
    
-   Make sure there aren't any scheduled integration jobs running on NetSuite ERP or the NetSuite EPM application.
    
-   (Optional) If you need an updated snapshot for the migration, create and archive the latest backup snapshot of the source environment. See [Backing up Artifacts and Application](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/epmss/export_dialog.html).
    
    Note:
    
    Cloning doesn't delete any existing snapshots or files in the inbox and outbox of the target environment. If **Artifact Snapshot** exists in the target environment, the application renames it as **Artifact Snapshot\_<DATE\_TIME>**. For example, Artifact Snapshot\_2021\_04\_30\_17:06:06.
    

**Target environment:**

-   Make sure you've selected the right NetSuite EPM business process.
    
-   If the target environment has multi-factor authentication (MFA) turned on, turn it off. Then, verify that you can log in without MFA. Cloning environments take only basic authorization credentials for the target environment.
    
-   Copy the URL for your target application as you'll need it to complete the cloning process.
    
    -   Example of production environment URL: `https://epm-idDomain.epm.dataCenter.oraclecloud.com/epmcloud`
        
    -   Example of test environment URL: `https://epm-test-idDomain.epm.dataCenter.oraclecloud.com/epmcloud`
