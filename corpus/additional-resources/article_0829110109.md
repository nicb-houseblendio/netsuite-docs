Important:

Before you start cloning a NetSuite Cloud EPM environment, make sire you've completed the prerequisites described in the help topic [Prerequisites for Cloning Environments](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0829112830.html).

Use the Clone Environment feature in your application to clone one environment to another target environment.

The cloning options that you see depend on the predefined role of the user account for the target environment. The following table lists the cloning options available for each predefined role.

| Predefined Role | Available Clone Options and Clone Restrictions |
| --- | --- |
| **Service Administrator** | You can clone application artifacts. You can also choose to clone Data Management records, audit data, Job Console records, inbox and outbox contents, and stored snapshots. You can't clone users or predefined role assignments. |
| **Service Administrator** and **Identity Domain Administrator** | You can clone application artifacts. You can also choose to clone users and their predefined role assignments, Data Management records, audit data, Job Console records, inbox and outbox contents, and stored snapshots. |

Note:

After the cloning process is done, all user accounts are automatically created in the target environment. Additionally, users will receive an email to activate their user account in the target environment.

#### To clone an environment:

1.  Log in to the source environment that you want to clone (the one you want copied).
    
    Sign in as a Service Administrator or as a Service Administrator, who's also an Identity Domain Administrator.
    
2.  For Profitability and Cost Management environments, click **Application**, and then click **Clone Environment**.
    
    For all other environments, click **Tools**, and then click **Clone Environment**.
    
3.  Next to **Cloning**, verify the snapshot's time stamp to make sure it includes the artifacts and data that you want.
    
    Note:
    
    If you made changes to the application after that time stamp, those changes won't be included when you clone the environment.
    
4.  In **Target URL**, enter the URL of the environment that you want to overwrite. For example, enter `https://epm-idDomain.epm.dataCenter.oraclecloud.com/epmcloud`.
    
5.  In **Username**, enter the user name for a user with the Service Administrator role, or both the Service Administrator and Identity Domain Administrator role.
    
    This user must be able to log in to the target environment with identity domain credentials.
    
6.  In **Password**, enter the identity domain password for the user that you entered in **Username**.
    
7.  (Optional) Check options that you want to clone, and clear options that you don't.
    
    For NetSuite Account Reconciliation, check all options except for **application audit** and **job console**.
    
    Important:
    
    You must have the Service Administrator and Identity Domain Administer roles to be able to clone users and their predefined roles. If a user who isn't an Identity Domain Administer checks **Users and Predefined Roles** and then clones an environment, importing users and their predefined roles will fail.
    
    For more information about these cloning options, see [Cloning Options and Key Considerations](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0829102132.html#subsect_0830095747).
    
8.  Click **Clone** to start.
    

After you start the cloning process, complete the steps described in [Post-Cloning Environment Tasks](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0830050821.html).
