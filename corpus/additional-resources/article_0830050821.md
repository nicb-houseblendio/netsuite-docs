After you clone an environment, if you're not using the source environment anymore, then make sure you complete the tasks described in this section. These steps ensure that the URLs, scripts, bookmarks, anything else set up for the source environment will work for the cloned environment.

Complete the following tasks after you clone an environment:

-   [Limit Access to Source Environment](#subsect_1004063607)
    
-   [Notify NetSuite Cloud EPM Users About the New URLs for the Cloned Environment](#subsect_0903052946)
    
-   [Update EPM Automate and REST API scripts](#subsect_0903053101)
    
-   [Update Task Manager, Supplemental Data Manager, and Enterprise Journal Custom Report Queries](#subsect_0903053154)
    
-   [Update Smart View URLs](#subsect_0903053239)
    
-   [Create New Vanity URLs](#subsect_0903053344)
    
-   [Update Bookmarks](#subsect_0903053420)
    
-   [Set Up Connection Between NetSuite and Target Environment](#subsect_0903053447)
    
-   [Update Integration With Other Services](#subsect_0903054542)
    
-   [Reconfigure SSO for Target Environment](#subsect_0903053619)
    
-   [Reconfigure IP Allowlist](#subsect_0903053652)
    
-   [Update IP address](#subsect_0903054700)
    

## Limit Access to Source Environment {#subsect_1004063607}

After cloning, you should consider allowing only one or two users to access the source environment and disable everyone else.

## Notify NetSuite Cloud EPM Users About the New URLs for the Cloned Environment {#subsect_0903052946}

Let NetSuite Cloud EPM users know about the new URLs for the cloned environment:

-   The URL to access the NetSuite Cloud EPM environment. For more information about these unique URLs, see [Sample URLs](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/1_epm_cloud_accessing_sample_urls.html) in the Oracle Help Center.
    
-   The URLs for setting up public and private Oracle Smart View for Office connections to the environment.
    

## Update EPM Automate and REST API scripts {#subsect_0903053101}

Update any EPM Automate and REST API scripts that you plan to run in the cloned environment. Make sure you change these values:

-   The environment URL.
    
-   The user's password, if it's different in the cloned environment.
    

## Update Task Manager, Supplemental Data Manager, and Enterprise Journal Custom Report Queries {#subsect_0903053154}

If needed, update Task Manager, Supplemental Data Manager, and Enterprise Journal custom report queries in the cloned environment. You might need to do this because internal IDs for objects (like tasks, journals, and attributes) can change during migration.

**Applies to:** NetSuite Planning and Budgeting, NetSuite Tax Reporting, and NetSuite Close Management and Consolidation.

## Update Smart View URLs {#subsect_0903053239}

Update the following Smart View URLs:

-   Update the public and private connection Smart View URLs so that they point to the cloned environment. See [URL Syntax for Smart View Connections](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/2_working_with_epm_clients_connect_url_syntax.html) in the Oracle Help Center.
    
-   Update connection URLS, if needed. See [About Managing Connection URL Mappings](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/svuuc/managing_url_mappings_100xfcbe6bf2.html) and [Updating Connection URL Mappings](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/svuuc/updating_url_mappings_100xfce25d93.html) in the Oracle Help Center.
    

## Create New Vanity URLs {#subsect_0903053344}

If your users connect with a vanity URL, create a new one or update the existing vanity URL to go to the cloned environment. See [Using Vanity URLs](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/cgsad/6_house_keeping_tasks_vanity_urls.html) in the Oracle Help Center.

## Update Bookmarks {#subsect_0903053420}

Remind users to update their bookmarks so that they go to the cloned environment.

## Set Up Connection Between NetSuite and Target Environment {#subsect_0903053447}

If you move many instances in an integrated business process to a new domain, please note that Single Sign On (SSO) won't work until all instances are migrated.

If you previously set up NetSuite to run jobs through the NetSuite interface,you'll need to update the connection to go to the new target environment. For more information, see the following help topics:

-   [Setting Up the Connection to Account Reconciliation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_5100827424.html#procedure_0221060306)
    
-   [Setting Up the Connection to Planning and Budgeting](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_158073354875.html)
    

## Update Integration With Other Services {#subsect_0903054542}

If your source environment was integrated with other services, review the integration settings to make sure that the cloned environment works with them too.

## Reconfigure SSO for Target Environment {#subsect_0903053619}

If you previously set up Single Sign-On (SSO) to authenticate users in the source environment, make sure you set up SSO in the new target environment too. This action ensures that users can log in without any issues. For more information, see [Configuring Single Sign-On](https://docs.oracle.com/pls/topic/lookup?ctx=en/cloud/saas/enterprise-performance-management-common/epmss&id=CGSAD-GUID-95FC749D-B76C-447B-867C-D61271C10ABE) in the Oracle Help Center.

## Reconfigure IP Allowlist {#subsect_0903053652}

If any of the following apply, you'll need to reconfigure the IP allowlists for your OCI environments by using the setIPAllowlist EPM Automate command:

-   You're migrating to OCI environments.
    
-   You haven't set up the IP allowlists as a prerequisite before cloning, or you want to change the configuration after cloning.
    

For more information about how to use the EPM Automand command, see the help topic [setIPAllowlist](https://docs.oracle.com/pls/topic/lookup?ctx=en/cloud/saas/enterprise-performance-management-common/cgsad&id=CEPMA-GUID-DDD0EB4B-3045-4224-9EC7-1686EC13B709) in the Oracle Help Center.

## Update IP address {#subsect_0903054700}

You need to update your IP address if you used the IP address for the source IP anywhere. For example, you might have added it in your proxy configuration as an allowed outgoing IP address. You can find the target environment's IP address by using **nslookup**. Alternatively, ping the IP address and update it.
