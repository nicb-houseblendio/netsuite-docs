Locations can be used to identify and categorize records in your NetSuite account. You can also define locations for your organization's needs by creating custom segments. Locations enable you to better organize data and preserve accuracy.

For information about working with locations in the UI, see [Classifications in NetSuite](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_N261411.html).

The REST API Browser includes information about the field names and field types of the location record, and about the HTTP methods, request parameters, and operations available to this record. For details, see the REST API Browser's [location](https://system.netsuite.com/help/helpcenter/en_US/APIs/REST_API_Browser/record/v1/2026.1/index.html#tag-location) reference page.

For information about using the REST API Browser, see [The REST API Browser](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157373386674.html).

## Record ID {#subsect_14090759972}

The record ID for the location REST record is **location**.

The location record has the following subrecords:

-   classTranslation
    
-   businessHours (as part of the Store Pickup feature)
    
-   mainAddress
    
-   inventoryBalance
    
-   returnAddress
    
-   tranNumbering
    
-   docNumbering
    
-   includeLocationRegions (as part of the Automatic Location Assignment feature)
    
-   excludeLocationRegions (as part of the Automatic Location Assignment feature)
    

## Limitations {#subsect_41090805262}

Read-only sublists, including system notes, are not supported in REST.
