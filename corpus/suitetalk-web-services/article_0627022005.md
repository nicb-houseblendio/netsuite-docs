NetSuite supports two mechanisms that increases overall system security. OAuth 2.0 and token-based authentication (TBA), robust, industry standard-based mechanisms. These authentication mechanisms enable client applications to use a token to access NetSuite through APIs, eliminating the need for integrations to store user credentials.

REST web services do not support login through user credentials. For general information about TBA, see [Token-based Authentication (TBA)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4247329078.html).

For general information about OAuth 2.0, see [OAuth 2.0](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_157769826287.html).

Note:

OAuth 2.0 is the preferred authentication method. You should consider using OAuth 2.0 instead of TBA whenever possible.

## Setting Up OAuth 2.0 Authentication for REST Web Services {#subsect_158202025145}

Tip:

For a step by step description of setting up OAuth 2.0 for REST, see [Tutorial: Using Postman with OAuth 2.0](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0602033701.html).

To set up OAuth 2.0, see [Getting Started with OAuth 2.0](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157771281570.html).

To be able to use REST web services with OAuth 2.0, you're required to create an application using an integration record. See [Create Integration Records for Applications to Use OAuth 2.0](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157771733782.html). As the last step of this procedure, make sure you note the client ID and client secret.

After creating the integration application, set up an application for use with OAuth 2.0. For more information, see [OAuth 2.0 for Integration Application Developers](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157780218434.html). After the application is set up, you can manage the authorized applications. For more information, see [Managing OAuth 2.0 Authorized Applications](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157771979135.html).

## Setting Up Token-Based Authentication (TBA) for REST Web Services {#subsect_1559218712}

Tip:

For a step by step description of setting up TBA for REST, see [Setting Up Token-Based Authentication (TBA) - Tutorial](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0605103340.html).

To set up TBA, see [Getting Started with Token-based Authentication](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4247337262.html).

To use REST web services with TBA, you must create an application using an integration record. See [Create Integration Records for Applications to Use TBA](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_4249032125.html). As the last step of this procedure, make sure you note the consumer key and consumer secret.

After creating the integration application, you're ready to create tokens for your users. Issue a new token for at least one of your users, and note its token ID and token secret. For details, see [Access Token Management - Create and Assign a TBA Token](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_4254081947.html).

After creating tokens, you use the token ID and token secret in your Postman environment. For information about setting up your environment, see [Importing and Setting Up a Postman Environment](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1545058149.html).

For detailed information about using TBA in integration applications, see [The Three-Step TBA Authorization Flow](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_156337186044.html).
