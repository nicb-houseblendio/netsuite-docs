A commerce category record exposes a commerce category to REST web services.

This record:

-   is not a subrecord
    
-   has no subrecords
    
-   has only sublists
    

The REST API Browser includes information about the field names and field types of the commerce category record, and about the HTTP methods, request parameters, and operations available to this record. For details, see the REST API Browser's [commerce category](https://system.netsuite.com/help/helpcenter/en_US/APIs/REST_API_Browser/record/v1/2026.1/index.html#tag-commerceCategory) reference page.

For information about using the REST API Browser, see [The REST API Browser](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157373386674.html).

## Record ID {#subsect_78095338371}

The record ID for a commerce category REST record is **commercecategory**.

## Prerequisites {#subsect_34095442802}

You must [Enable Commerce Categories Feature](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4670512771.html) for any interaction with the record. The account must also contain a Commerce Catalog record to reference.

## Inaccessible Elements {#subsect_51095511819}

The following sublists are not accessible through REST web services:

-   URL Fragment Aliases sublist is not exposed
    
-   "isCurrentlyEffective is internal only
    

## Elements with Different Functionality {#subsect_94095604852}

Updating the tags collection using REST does not delete removed tags, it only adds new tags and updates existing tags.

## Additional Details {#subsect_69095637663}

The "displayinSite" field values must be "T" or "F", not standard boolean.

The "sitemapPriority" field values must be a string with possible values between "0.0" and "1.0" incrementing by tenths. For example, ("0.1", "0.2", "0.3", etc.). This behavior is the same across all channels, not specific to REST web services.
