Note:

Install NetSuite CPQ Manufacturing to use routing steps from configured items in work orders. For more information, see [Installing NetSuite CPQ SuiteApps](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_1145912241.html).

Routing steps are the tasks required to build a configurable item. If your configurable item is a desk, examples of routing steps may be cutting and polishing the wood for the top surface and the side panels.

To include a routing step in a work order, assign the routing step to a material through the **Routing Step** field on the material record. For more information, see [Defining Materials for the Configurable Item](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_7143710234.html).

A routing step is added to configurations and later to work orders if its rule matches the answers users select on the product interface. For more information, see [Activating or Hiding Building Blocks with Rules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_4124359628.html). You can view active routing steps under the **Routing Steps** option in the Audit menu on the product interface.

When users click the **Convert WO** button on the sales order, routing steps are added under the **Operations** subtab of the work order. Each routing step becomes a manufacturing operation task, which is a subrecord of the work order. For more information about creating work orders, see [Creating Work Orders for Configured Items](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8155327253.html).

When adding a routing step as an operation task to the work order, you can set fields for the routing step by selecting mapping records in the **Line Field Mapping Records** field during the setup. In the **Common Line Field Mapping Records** field, you can view the mapping records automatically applied to all routing steps. These mapping records have the **Apply to all routing steps** box checked. For more information about mapping records, see [Setting Transaction Body and Line Fields Based on Configuration Data](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8153202018.html).

#### To create a routing step:

1.  In NetSuite, go to CPQ > Configurator > Product Maintenance.
    
2.  Click **Edit** next to the product you want to modify.
    
3.  On the **Routing Steps** subtab, click **New CPQC Routing Step**.
    
4.  Enter a descriptive name for this routing step.
    
    This name is displayed under the **Routing Steps** option in the Audit menu on the product interface. It's also used as the operation name under the **Operations** subtab of the work order.
    
5.  In the **Code** field, enter a unique identifier for this routing step.
    
    You can use a shortened version of the name as the code. The code can contain only uppercase letters, numbers, and underscores.
    
6.  (Optional) In the **Description** field, enter a brief explanation of this routing step.
    
    This description is used for internal reference only.
    
7.  Complete the basic fields for the manufacturing operation task record:
    
    -   The **Comments** field. Its content is displayed on the product interface under Audit > Routing Steps.
        
    -   The fields in the Operation Properties section: **Operation Sequence**, **Setup Time (min)** , **Run Rate (min/unit)**, **Manufacturing Work Center**, **Manufacturing Cost Template**. For more information, see [Manufacturing Operation Tasks](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2346668.html).
        
        To obtain information from the configuration, you can enter resolve expressions in the **Comments**, **Setup Time (min)** and **Run Rate (min/unit)** fields. For more information, see [Obtaining Answer Data with Resolve Expressions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_2144102668.html).
        
8.  (Optional) To define a specific date range in which this routing step is active and can be added to the configuration and later to the work order:
    
    -   In the **Effective Start Date** field, select a start date.
        
        Before this date, the routing step is inactive.
        
    -   (Optional) In the **Effective End Date** field, select an end date.
        
        After this date, the routing step is inactive.
        
    
    Note:
    
    If you define a date range, the routing step must meet both the date range and the conditions in its rule to be active.
    
9.  (Optional) In the **Line Field Mapping Records** field, select the mapping records you want to use to set fields for the routing step when it's added as an operation task to the work order. For more information about mapping records, see [Setting Transaction Body and Line Fields Based on Configuration Data](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8153202018.html).
    
10.  In the **Rule** field, provide the condition that determines whether this routing step is added to the configuration and later to the work order.
     
     Enter question and answer codes separated by a forward slash, for example, A/1. Use operators to combine multiple conditions, for example, A/1&B/2.
     
11.  Click **Save**.
     

To copy or delete routing steps, see [Working with Product Building Blocks](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_0926032123.html).
