## SP-initiated and IdP-initiated Flows {#subsect_1520981958}

There are two single sign-on flows in the SAML 2.0 standard: SP-initiated and IdP-initiated. NetSuite supports both types of flows.

For more information about SAML SSO use with web stores, see [SAML Single Sign-on Access to Web Store](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_3940510119.html).

### The SP-initiated Flow {#subsect_1527773566}

To trigger an SP-initiated flow:

-   SAML must be set as a primary authentication method, or:
    
-   A user should have a browsing history using SAML, and a deep link should be used to trigger the flow.
    

For more information, see the [Primary Authentication Method](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3826794.html#subsect_1528125879) in [Defining the NetSuite Configuration for SAML](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3826794.html#bridgehead_N3826895).

#### SAMLRequest and RelayState {#subsect_1517946121}

To initiate the login protocol exchange, the SAMLRequest must be in an SP-initiated flow. RelayState is an optional parameter to preserve and convey state information that is transferred with the SAMLRequest message. For detailed information, refer to the SAML 2.0 specification. Go to [https://www.oasis-open.org/standards#samlv2.0.](https://www.oasis-open.org/standards#samlv2.0)

You can configure the value of the RelayState attribute on the IdP side. However, for security reasons, NetSuite does not support redirects to external pages (other than NetSuite pages) through RelayState attribute in the SAML assertion.

## Single Logout (SLO) {#subsect_1520897481}

NetSuite supports Single Logout (SLO) feature. The following Single Logouts (SLO) are supported:

-   IdP-initiated SLO is supported for the NetSuite UI and Commerce web stores.
    
-   SP-initiated SLO is supported for the NetSuite UI and Commerce web stores.
