Currently, the Device ID feature is intended for use with Suite Commerce InStore (SCIS) SuiteApp and the point-of-sale (POS) devices running the SCIS POS application.

For more information about SCIS, see [SuiteCommerce InStore Administrator's Overview](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4233587672.html). See also, [Configuring the SCIS Mobile App](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161350254557.html).

The first time a user attempts to log in to SCIS on a device running the SCIS POS application, a unique device identifier is sent to NetSuite. The name of the device is also sent. With this information, a device record is created in NetSuite in **Pending** status. Users can't log in to SCIS with the device until an administrator reviews the device record and changes the device status to to **Trusted**. This ensures that only devices approved by the administrator can be used to log in. The administrator can also change the device status to block a device, or mark a device record as on hold.

When the SuiteCommerce InStore SuiteApp is installed in a NetSuite account, it automatically creates a role restricted by device ID. This is the only role allowed to log in to SCIS on a device configured with the SCIS POS application.

Users with device ID role trying to log in using an unauthorized device receive the error message "No device id role was found". The user must contact an administrator and request an SCIS device ID role.

Administrators can create additional device ID restricted roles if preferred, using the SCIS-created roles as a template. For more information about SCIS roles, see [SCIS Roles and Permissions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4230734733.html).

Note:

Users with device ID-restricted roles aren't asked security questions. See [Setting Up Security Questions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1548704486.html) for more information.
