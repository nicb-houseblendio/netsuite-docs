If appropriate, you can use the Token-Based Authentication (TBA) feature to authenticate when calling RESTlets. With TBA, you use the OAuth 1.0 specification to construct an authorization header. For details, see the following topics:

-   [TBA Setup Requirements](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4636903496.html)
    
-   [The Three-Step TBA Authorization Flow](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_156337186044.html)
    
-   [Example OAuth Header](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4635758034.html)
    
-   [Tracking RESTlet Calls Made with TBA and OAuth 2.0](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4567507062.html)
    

Note:

If you're calling a RESTlet from an external source, you must authenticate by using TBA, OAuth 2.0 or user credentials. For details on user credentials, see [Using User Credentials for RESTlet Authentication](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4623992425.html). For details on OAuth 2.0, see [Setting up OAuth 2.0 for a RESTlet Integration](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_158263562006.html).
