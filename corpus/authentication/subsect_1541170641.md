### Is encryption required? {#question_1541182395}

As stated in the NetSuite Service Provider (SP) metadata, encryption is not required. At minimum, it is required only that assertions be signed (WantAssertionsSigned="true"). But an identity provider (IdP) can set a higher level of security using encryption. Refer to the SAML specifications to learn more about the encryption options SAML supports.

### What Secure Hash Algorithm (SHA) is supported, SHA1 or SHA256? {#question_1541182170}

The answer to this question is tied to the SAML 2.0 protocol. SAML relies on the XML-Signature Syntax and Processing specification (D. Eastlake and others, XML-Signature Syntax and Processing. World Wide Web Consortium, February 2002.) For more information, see [http://www.w3.org/TR/xmldsig-core/](http://www.w3.org/TR/xmldsig-core/). The only supported hashing function in this specification is SHA1. You should use the RSAwithSHA1 signature method.

### What bindings are supported?

NetSuite does not support non-secure bindings. All of the bindings require TLS. Our Assertion Consumer Service only accepts the HTTP-POST binding. This is described in the Service Provider Metadata file. To view the NetSuite SP metadata file in your account, see [Prepare to Provide NetSuite SP Metadata to Your IdP](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1520724744.html).

### Do all SAML 2.0 messages have authenticity and integrity protection using a digital certificate? {#question_1541171769}

The whole assertion message must be signed by the IDP private key and sent over HTTPS. NetSuite only supports use of the TLS 1.2 protocol for secure communication.

### Does the Response for any message that does not have authenticity and integrity protection always indicate failure? {#question_1541171821}

Yes, it does. At a minimum, NetSuite requires that an assertion be signed.

### If a message or elements of a message are digitally signed, does the relying party always validate the public key of the digital signature? {#question_1541171894}

Yes, it does.

### Are there any revocation checks done against the signature (such as CRL or OCSP)? {#question_1541171986}

There are no automatic checks. The revocation must be done by an administrator, by removing an IDP's metadata from the NetSuite account settings.

### Are all SAML 2.0 messages sent through an HTTP binding using the Transport Layer Security (TLS) protocol? {#question_1541171001}

NetSuite only accepts requests sent through HTTPS (TLS). NetSuite only supports use of the TLS 1.2 protocol for secure communication.

### Does the Service Provider process the InResponseTo attribute of the Response to ensure the Response was intended for them and is still fresh? {#question_1541176049}

For the SP-initiated flow, this check is included as per the SAML standard. Both IdP-initiated and SP-initiated flows are supported. See [Interactions with NetSuite Using SAML](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1520981877.html) for more information.

### Does the Service Provider process the Destination attribute of the Response to ensure the Response was intended for them? {#question_1541181555}

Yes, it does.

### Does the Service Provider process the SubjectConfirmationData element to ensure the Assertion was intended for them? {#question_1541181606}

Yes, it does.

### Does the Service Provider validate the NotOnOrAfter attribute of the Conditions element to ensure the Assertion is still fresh? {#question_1541181650}

Yes, it does.

### Does the Service Provider process the AudienceRestrictions element to ensure the assertion was intended for them? {#question_1541181718}

Yes, it does.

### Does the Service Provider process the AuthnContext element to ensure class of Authentication? {#question_1541181762}

Yes, it does.
