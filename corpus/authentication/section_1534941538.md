This section covers how to track tokens and users with the Login Audit Trail and provides details about error messages you might encounter.

## Track TBA Tokens and Users {#subsect_1534941869}

You can use the Login Audit Trail to track TBA tokens and users.

#### To track tokens and users: {#procedure_4253316921}

1.  Go to _Setup > Users/Roles > User Management > View Login Audit Trail_.
    
2.  Check the **Use Advanced Search** box.
    
3.  Click the **Results** subtab.
    
4.  Add the following fields: **Detail**, **Token-based Access Token Name**, and **Token-based Application Name**.
    
5.  Click **Submit**.
    
    The **Detail** column displays error messages for any token-based authentication logins with a status of Failure.
    

For more information about defining Login Audit Trail searches, see [Login Audit Trail Overview](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N324233.html).

## TBA-Related Error Messages in the Login Audit Trail {#subsect_1520451531}

A good place to start troubleshooting TBA problems is the Detail column in the Login Audit Trail Results. RESTlets, SOAP, and REST web services have slightly different error messages, but they mean about the same thing.

For more information about error messages, see the following sections:

-   [Error Messages for RESTlets, SOAP Web Services, and REST Web Services](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_156935170194.html)
    
-   [Error Messages for the TBA Authorization Flow](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_156934879823.html)
    

Note:

Tokens created using the Token-based Authentication feature in your NetSuite production account are not copied to your Release Preview or to your sandbox accounts. To test this feature in Release Preview or in a sandbox, you must create new tokens in that account. Each time the sandbox is refreshed, you must create new tokens in the sandbox.
