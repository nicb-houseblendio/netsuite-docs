Lookups define relationships between the platform variables, helping the Salesforce Connector ensure data integrity. Lookups are defined on the Manage Lookups page.

All required Lookups are automatically populated during the setup of the Salesforce Connector.

The following table contains information about locating lookup sources in both NetSuite and Salesforce.

| Lookup | Location In NetSuite |
| --- | --- |
| Units of Measure | The Multiple Units of Measure feature enables you to define various units used to stock, purchase, and sell inventory items, and track non-monetary accounts. To view Multiple Units of Measure in NetSuite, go to Lists > Accounting > Units of Measure.
-   The Multiple Units of Measure feature must be enabled in your NetSuite account. To enable this feature, go to _Setup > Company > Setup Tasks > Enable Features_
-   For more information, see the following topics:
    -   [Multiple Units of Measure](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_N2164525.html#subsect_161912136173)
    -   [Setting Up Units of Measure](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2212143.html). Go to _Lists > Accounting > Units of Measure > New_

Refer to [Add a Unit of Measure](https://help.salesforce.com/s/articleView?id=sf.cg_task_admin_add_uom.htm) for information about managing Unit of Measure in Salesforce. Note: Only active Unit of Measure values are displayed. Unit of Measure is not required for Non-inventory items. |
| NetSuite Price Levels | See [Editing Price Levels](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2182796.html) or go to Setup > Accounting > Setup Tasks > Accounting Lists. Refer to [Manage Price Books](https://help.salesforce.com/s/articleView?id=sf.pricebooks_landing_page.htm) for information about managing Price Books in Salesforce. Note: You should have 1:1 mapping for NetSuite Price Levels and Salesforce Price Levels. NetSuite is considered the authoritative source. If you do not maintain price levels in NetSuite, Salesforce prices are still synced as custom price in Sales Orders and as null on NetSuite Items. |
| Country Codes | See [Country Enumerations](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3785183.html) for the list of country codes in NetSuite. Refer to [Standard Countries and Territories for Address Picklists](https://help.salesforce.com/s/articleView?id=sf.admin_state_country_picklists_standard_countries.htm) for information about managing country codes in Salesforce. |
| Currency Codes | To view the currencies defined in NetSuite, go to Lists > Accounting > Currencies. See [Creating Currency Records](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N1395911.html) for information about adding more currencies to the list. Refer to [Supported Currencies (ICU)](https://help.salesforce.com/s/articleView?id=sf.admin_supported_currencies.htm) in the Salesforce documentation for information about managing currencies in Salesforce. |

## Require Prices for All Mapped Currencies {#subsect_0622072403}

This setting in the Currency Lookup screen prevents the issue that occurs when items that have multiple currencies in one system and single currency in another. This setting is set to disabled by default so that only the currencies that have prices in the items will be synced.

If you enable this setting, the item is only synced if all the NetSuite currencies configured have prices in the respective item in Salesforce.

## Country Codes and State Codes {#subsect_0622073306}

Country Codes show Salesforce Country Code, Salesforce State Code, NetSuite Country Code, and NetSuite State Code where applicable. The State Codes lookup displays state code mappings by country, with United States selected by default and Canada available for selection. You can update state code values and save changes back to the lookup table in Edit mode. You can't remove country or state code lookup rows.
