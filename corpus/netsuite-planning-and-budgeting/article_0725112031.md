You can clone and customize any of the supported metadata saved searches. To create a hierarchy of metadata you want to export in a saved search, you can add columns to the metadata saved search result.

#### To customize and add columns to a metadata saved search: {#procedure_0725112034}

1.  Go to _Reports > Saved Searches > All Saved Searches_ to clone an existing metadata saved search.
    
2.  Click **Edit** next to a metadata saved search of your choice.
    
3.  Change the saved search title.
    
4.  Click **Save As**.
    
    This clones the saved search.
    
5.  On the Saved Searches page, click **Edit** next to the cloned saved search.
    
6.  Verify that the saved search is public.
    
7.  Click **Change ID**, and append an alphanumeric value to the saved search ID.
    
    Note:
    
    Make sure you don't change the original saved search ID, and only append a value to the original saved search ID.
    

<a id="step_44144002141"></a>

9.  On the **Results** subtab, add the new columns after the existing columns.
    
    Important:
    
    Make sure you apply the following best practices for adding the new columns:
    
    -   Enter a **Custom Label** value for every column you add to the saved search result.
        
    -   Add columns with unique **Custom Label** values. If you add duplicate columns, the generated saved search result may not be imported successfully to your Planning and Budgeting.
        
    
    The following list gives details about customizing columns for metadata saved searches:
    
    -   NSPB Sync doesn't support any values in the Summary Type column for metadata.
        
    -   You can't customize the Parent column and the Data Storage formula.
        
    -   For Accounts metadata saved searches, you can't customize the Alias: Default formula.
        
10.  Make any other necessary changes, and click **Save**.
     

The following list gives details about the metadata saved search customization and hierarchy:

-   Customization of metadata saved searches only works when you call RESTlets from Data Exchange.
    
-   When a metadata saved search is filtered, the RESTlet returns a complete parent-child hierarchy.
    
-   When you clone a metadata saved search and add columns to it in NetSuite:
    
    -   The dummy parents created for the columns in your Planning and Budgeting inherit the property values from the NetSuite parents.
        
    -   The fixed metadata columns don't need to be set as the first columns or in a specified order in the saved search result. If you omit or reorder columns in the saved search hierarchy, NSPB Sync includes the missing columns in the saved search result. NSPB Sync also corrects the order of the columns in the saved search result.
        
-   If your preferred language differs from your account's default language, data loaded in Data Exchange may differ from the saved search result generated in NetSuite for the same saved search.
