Valid companies can switch to Intelligent Payment Automation, powered by BILL, if you use either Electronic Bank Payments or Payment Automation with HSBC SuiteApp. When you install the Intelligent Payment Automation SuiteApp, your vendor's bank accounts that have a U.S. address are automatically migrated to the Payment Instrument record that stores bank details. It also migrates remittance details.

Intelligent Payment Automation migrates the details of the vendor's U.S. primary bank only. Within a vendor record, you can verify the primary bank details through one of the following ways:

-   If you use Electronic Bank Payments, you can verify the primary bank on the **Bank Payment Details** subtab. For more information, see [Setting Up Bank Records of Vendors in the U.S.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N1660722.html)
    
-   If you use Payment Automation with HSBC, you can verify the primary bank on the **SuiteBanking** subtab. For more information, see [Vendor Bank Data](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1006112830.html#subsect_88161946128).
    

Note:

Here are a few things to note about migrating to Intelligent Payment Automation:

-   If you use both SuiteApps, vendor remittance and primary bank details associated with Payment Automation with HSBC are prioritized for migration.
    
-   This migration does not overwrite any existing Payment Instrument records.
    
-   After the migration is complete, NetSuite sends an email with the migration results. If the migration is successful, the email confirms that the migration completed successfully. If the migration fails, the email includes details about the failure. Review the email for information about any records or issues that require attention.
    

To view migrated bank details using the Administrator role, access a vendor record in view mode by going to Lists > Relationships > Vendors. On the **Financials** subtab, click the **Payment Instruments** subtab, and then click **Edit** next to the payment instrument record. For more information about vendors, see [Creating Vendors for Intelligent Payment Automation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0729012011.html).

After you create a BILL payment account, vendor records with open AP balances are automatically synced with BILL along with their banking details, which are stored in the Payment Instrument record. You can pay U.S. vendors through payment options available from BILL. You can continue processing payments for non-U.S. vendors through Electronic Bank Payments.

Intelligent Payment Automation provides roles that you can assign to your payment managers and clerks. You can update your existing custom roles with permissions to use Intelligent Payment Automation capabilities.

For more information about availability, fees, and subsidiaries, see [Intelligent Payment Automation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8155141819.html) or [Intelligent Payment Automation FAQs](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0530033225.html).

To start switching to Intelligent Payment Automation, see [Setting Up Intelligent Payment Automation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0530033102.html)

## Handling Common Migration Issues {#subsect_1003021813}

If you encounter the following issues during or after the migration of your vendor bank accounts, follow the corresponding guidelines or instructions:

**ISSUE**: Migration failed or did not get completed.

**ACTION**: If you encounter unexpected migration issues, you can manually deploy the following script:

-   Script Name: **NSNPA - Bank Account Migration MR**
    
-   Deployment Script ID: **customdeploy\_nsnpa\_mr\_bankacct\_migration**
    

For instructions, see [Deploying a Script by using the Script Deployment Record](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0706024425.html).
