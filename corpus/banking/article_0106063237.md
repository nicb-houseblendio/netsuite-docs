This topic lists all standardized error codes and scenarios for bank import processes, grouped by error type and file format. Standardized error messages only appear in NetSuite for automatic imports if the required plug-in updates have been made. If you're a plug-in author, see the next section for update instructions.

Standardized codes for parser-level and import-level errors are automatically available for manual imports that use default Bank Administration Institute version 2 (BAI2) and Comma-Separated Values (CSV) parsers, with no parser plug-in updates required. If multiple issues are found in a file, these errors are captured and displayed on the Banking Import History page. Errors are often shown with line number and position to support more precise troubleshooting.

## Plug-in Author Action Required {#bridgehead_0106063335}

To ensure that standardized error messages for automatic bank import processes appear in NetSuite, update your custom or third-party plug-ins accordingly. Without these updates, only error messages written by the plug-in author (custom messages) or generic error messages appear. The following plug-in updates are required:

-   Adding the `errorCode` field in your Financial Institution Connectivity Plug-in for account errors. See [Updating Connectivity Plug-ins for Account Error Codes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0106075610.html).
    
-   Implementing the `addError` API in your Financial Institution Parser Plug-in for parser-level errors. See [Updating Parser Plug-ins for Parser Error Codes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_94201350937.html).
    
-   Adding import-level standardized error handling in Financial Institution Parser Plug-ins and Financial Institution Connectivity Plug-ins. See [Updating Parser Plug-ins for Import Error Codes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_15230408833.html) and [Updating Connectivity Plug-ins for Import Error Codes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_90212014023.html).
    

After making these updates, update your plug-in's code so that each error scenario you handle returns or sets the correct error code that's listed in this topic.

If you see a free-text failure reason in the UI, a warning displays (visible with the Financial Institution Records permission with "Edit" access). This warning is a signal that the plug-in hasn't been updated for error code support. Free-text failure reasons are targeted for removal in a future release, but plug-in updates for error code support are strongly encouraged as soon as possible.

## Error Code Structure {#bridgehead_0106064107}

All error codes follow this pattern: XYYYNNNNZZ

Each part of the code provides specific information about the error:

-   **X** - Error scope/type:
    
    -   0: File/import-level error
        
    -   1: Record-level error (transaction, balance, and so on)
        
    -   2: Account-level error
        
-   **YYY** - Data format:
    
    -   000: Format-agnostic
        
    -   010: CSV (standard template)
        
    -   020: BAI2
        
    -   030: CAMT053 - ISO 20022 Cash Management Bank to Customer Statement message
        
-   **NNNN** - Specific numeric error identifier
    
-   **ZZ** - Code variant or subtype (context-specific)
    

This format helps you quickly determine the type, context, and specifics of any error reported in a bank import process.
