Intelligent Transaction Matching runs built-in matching rules to match imported data with existing account transactions in NetSuite. You can find these rules on the Reconciliation Rules page, although you can't edit or remove them. NetSuite prioritizes system rules in the following order:

-   [Match on Transaction Number and Amount](#bridgehead_4744760171)
    
-   [Match on Amount and Transaction Number without Prefixes and Leading Zeros](#bridgehead_4744760918)
    
-   [Match on Amount when Date is within 3 Previous Days](#subsect_0414105050)
    
-   [Match on Amount when Date is within 90 Previous Days](#bridgehead_4744761788)
    

Note:

If a rule finds two or more possible matches, the rule can't match the transaction automatically. However, if the Enriched Bank Data feature is enabled (turned on by default), NetSuite may still be able to automatically match the transaction using enriched details. For details, see [Enriched Bank Data for Transaction Matching](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0305111754.html).

If two or more candidate transactions are still equally plausible based on the available details, you must review the candidates and manually select the correct match.

For system rules to automatically match transactions based on the transaction number, they must match the Transaction ID from the imported bank line with the NetSuite Check Number. The NetSuite Check Number corresponds to the:

-   Check # on Bill Payments, Checks, Customer Payments, and Cash Sales.
    
-   Deposit # on Deposits.
    
-   Transfer # on Transfers.
    
-   Entry No. on Journal Entries.
    
-   Reference # on Credit Card Charges and Credit Card Refunds.
    

For details, see [Transaction Types in Matching Rules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1506624083.html).

## Match on Transaction Number and Amount {#bridgehead_4744760171}

Using this rule, Intelligent Transaction Matching matches imported bank lines to account transactions when these criteria are met:

-   The imported transaction ID exactly matches the account transaction check number (NetSuite Check Number).
    
-   The amount is an exact match.
    
-   The account transaction date is the same as or before the imported transaction date.
    

This rule also attempts to find matches for groups of transactions with the same transaction number. For many-to-one or many-to-many matches, Intelligent Transaction Matching matches transactions when the sum of imported bank line amounts equals the sum of account transaction amounts. For details on these match types, see [Many-to-One Transaction Matches](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_202608110005.html) and [Many-to-Many Transaction Matches](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_202608110007.html).

If these criteria aren't met, Intelligent Transaction Matching runs the next active system (default) rule.

## Match on Amount and Transaction Number without Prefixes and Leading Zeros {#bridgehead_4744760918}

Using this rule, Intelligent Transaction Matching matches imported bank lines to account transactions when these criteria are met:

-   The transaction numbers differ only by formatting, so they match after comparing only the numeric value of the transaction number. For example:
    
    -   Transaction numbers differ only by an alphabetical prefix (for example, `N123` and `123`).
        
    -   Transaction numbers differ only by leading spaces (for example, `123` and `.123`). In this example, a dot was used to represent a leading space because a leading space doesn't render properly here.
        
    -   The transaction number differs only by leading zeros (for example, `000123` and `123`).
        
-   The amount is an exact match.
    
-   The account transaction date is the same as or before the imported transaction date.
    

This rule also attempts to find matches for groups of transactions with the same numeric value.

If these criteria aren't met, Intelligent Transaction Matching runs the next active system (default) rule.

## Match on Amount when Date is within 3 Previous Days {#subsect_0414105050}

Using this rule, Intelligent Transaction Matching matches imported bank lines to account transactions when these criteria are met:

-   The imported amount is equal to the amount of the account transaction in NetSuite.
    
-   The account transaction date is the same as or up to 2 days before the imported transaction date.
    

This rule uses a 3-day date range that includes the imported transaction date.

Because this rule doesn't check the transaction number, NetSuite doesn't group transactions by it. For details, see [Grouping Multiple Transactions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_202608110008.html).

If these criteria aren't met, Intelligent Transaction Matching runs the next active system (default) rule.

## Match on Amount when Date is within 90 Previous Days {#bridgehead_4744761788}

Using this rule, Intelligent Transaction Matching matches imported bank lines to account transactions when these criteria are met:

-   The imported amount is equal to the amount of the account transaction in NetSuite.
    
-   The account transaction date is the same as or up to 89 days before the imported transaction date.
    

This rule uses a 90-day date range that includes the imported transaction date.

Because this rule doesn't check the transaction number, NetSuite doesn't group transactions by it. For details, see [Grouping Multiple Transactions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_202608110008.html).

If these criteria aren't met, Intelligent Transaction Matching tries the first active custom rule, if there is one. For details, see [Creating User Transaction Matching Rules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_160002098350.html).
