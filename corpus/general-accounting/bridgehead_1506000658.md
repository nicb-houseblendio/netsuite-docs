Before you create an approval rule, take note of the following reminders:

-   You can create multiple approval rules for a record type if each rule has a unique criteria. For more information about uniqueness validation, see [Approval Rule Validation](#bridgehead_1527054045).
    
-   If you want to use saved searches in approval rules, create saved searches of transaction records before you create approval rules. For guidelines and instructions for defining saved searches, see [Saved Searches](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_N675442.html).
    
    Tip:
    
    Make sure you remember the titles of your saved searches when you define or update them. Remembering the titles will save you time when creating approval rules.
    
    You don't have to select a saved search when creating approval rules. The workflow filters records for approval based on the transaction amount or employee limit, depending on your Approval Routing settings. However, the system still considers the Saved Search Condition field during approval rule uniqueness validation. If you use saved searches in multiple approval rules, configure the saved searches to return distinct sets of records so that each approval rule applies to the intended records.
    
-   The **Saved Search Condition** field can load a maximum of 4,000 public saved searches for each user.
    
-   By default, an approval rule locks records that are **Approved** or **Pending Approval**. You can only edit and resubmit a record for approval if its status is **Rejected**. For more information, see [Resubmitting Records for Approval](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_1506060896.html).
    
-   If you enabled the required features for project-based approval, the Project Manager approver type is added to the approval matrix. For more information, see [Enabling Prerequisite Features for SuiteApprovals](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_1504484325.html).
    
    Project-based approvals apply only to expense reports, purchase orders, or vendor bills linked to projects.
    
-   SuiteApprovals can process up to 18,000 approver records for each NetSuite account. Take note of the following record category limits:
    
    | Record | Limit |
    | --- | --- |
    | Employee | 10,000 |
    | Role | 4,000 |
    | Group | 4,000 |
    
    If you exceed any of the category limits or the combined record limit, you may get an error when you create approval rules.
    
-   Make sure you know who the required approvers are for expense reports. For more information about supervisor and expense approver approvals, see [Approving an Expense Report](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2396195.html).
    

## Approval Rule Validation {#bridgehead_1527054045}

SuiteApprovals validate approval rules based on the following criteria:

1.  Approval rule uniqueness. The system checks the following fields and values:
    
    1.  Name
        
    2.  Priority
        
    3.  Saved Search Condition
        
    4.  Unique combination of the following:
        
        -   Record Name
            
        -   Subsidiary
            
        -   Start Date
            
        -   End Date
            
        -   Status: Running
            
    
    If you create an approval rule without selecting a saved search condition, make sure no other running approval rule has the same record type, subsidiary, and overlapping effective date range.
    
    Watch the following help video for information about approval rule uniqueness:
    
    <a id="kaltura_player_125"></a>
    
2.  The system checks for running approval rules. If there are multiple, the rules are evaluated by priority and activates the one with the highest priority.
    
    If the system finds an active approval rule with no assigned priority, that rule is used first by default.
    
3.  The rule checks if the record meets any saved search criteria. The following list explains the possible outcomes:
    
    -   If the rule matches a record, the workflow proceeds.
        
    -   If the rule doesn't match, the system runs the rule with the next highest priority, and continues until a match is found.
        
    -   If no rule matches, the record exits the approval workflow and you must approve the record manually.
