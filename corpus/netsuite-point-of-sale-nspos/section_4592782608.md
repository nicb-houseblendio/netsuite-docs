NSPOS includes support for gateway services provided by Worldpay (Vantiv). This gateway provider was previously called Mercury Payment Systems (MPS).

Important:

NSPOS support for the Worldpay (Vantiv) \[Mercury Payment Systems (MPS)\] gateway is available only for NSPOS 2024.1.X or a prior release. This payment gateway is not supported for NSPOS 2025.1.X or later.

For information about starting with Worldpay, visit their site at [www.worldpay.com](http://www.worldpay.com). Worldpay will provide installation instructions for the client terminal setup on your registers. You must configure your RA-Workstation records in NetSuite ERP to accept Worldpay (Vantiv) \[Mercury Payment Systems\].

EMV support by Worldpay (Vantiv) \[Mercury Payment Systems\]. is enabled by integration with a dsiEMVUS client using a time-stream settlement method. Also known as auto-close, this method is a time-initiated settlement that closes the batch process automatically.

## Supported Transaction Types {#bridgehead_1519663981}

**Credit:**

-   EMVParamDownload
    
-   EMVSale
    
-   EMVReturn
    
-   EMVVoidSale/Return
    
-   EMVVoiceAuth
    
-   EMVVoidSale
    
-   EMVVoidReturn
    

**Settlement Method:**

-   Time-Stream
    

**Functionality:**

-   dsiEMVUS™ (requires DataCap Systems In-Store NETePay ®)
    
-   Mercury E2E
    
-   Mercury Tokenization, MToken™
    

## How it works {#bridgehead_4586625839}

The Datacap dsiEMVUS uses a locally installed Windows ActiveX control - dsiEMVX - that serves as the application interface between the POS, the EMV device, and Datacap's US EMV-certified in-store NETePay. The dsiEMVX:

-   Directly controls an EMV device through a PC port (Serial/RS232 or USB using a Virtual COM port) to manage all PIN pad interactions.
    
-   Uses XML-formatted requests and responses for transaction processing. It makes all non-sensitive request and response XML data available for POS payment logs.
    

When the POS initiates an EMV transaction, the dsiEMVUS takes control of the PIN pad device. The chip card and card reader negotiate to determine debit or credit, the verification method and other parameters. The chip card generates the authorization ARQC, sending it to dsiEMVUS which in turn passes it to the Worldpay (Vantiv) processor. Worldpay (Vantiv) connects with the card issuer and returns a final authorization through dsiEMVUS to the device and POS.

## Supported Devices {#bridgehead_4586625896}

These PIN pads are supported by Worldpay (Vantiv) for EMV transactions in NSPOS:

-   Datacap Systems dsiEMVUS
    
-   Ingenico ISC250 (with signature capture \*)
    
-   Ingenico Lane/3000
    
-   Ingenico Lane/7000 (with signature capture \*)
    
-   Verifone P400
    
-   Verifone VX805 enabled with End-to-End Encryption (E2EE)
    
    \* Available in NSPOS 2020.1.10 and later.
    

To check if another device is supported for dsiEMVUS, please contact your Worldpay (Vantiv) representative.

Note:

Although the Worldpay setup options in NetSuite might show Mercury Payment Systems, your setup will automatically apply to the new company name - Worldpay (Vantiv).

Important:

These steps require an update to each RA-Workstation on which you want to configure and use the Worldpay (Vantiv) gateway.

#### To set up the Worldpay (Vantiv) EMV payment gateway:

1.  Log in to NetSuite as an administrator.
    
2.  Go to _Customization > Lists, Records, & Fields > Record Types_.
    
3.  Locate the **RA-Workstation** row and click **List**.
    
4.  Click **Edit** for the first workstation to update.
    
5.  For **Payment Provider**, select **Mercury Payment Systems**.
    
6.  In the **Payment provider info** section, complete the following fields:
    
    -   **Merchant** - Enter the Merchant ID (MID) provided by Worldpay (Vantiv).
        
        The Merchant ID identifies the account both internally and externally for your POS configuration and for transmitting banking information and deposits. It includes a range of attributes that parallel the POS system's functionality.
        
        Warning:
        
        If the Worldpay (Vantiv) system value isn't synchronized with the value at the POS, processing can fail at the merchant location. For example, if the POS is processing using `E2EE`, then the Merchant ID must be `E2EE`.
        
    -   **Terminal ID -** Called the SecureDeviceID by Worldpay (Vantiv), this is the device identifier. The supported values are:
        
        -   Ingenico ISC250 device: `EMV_ISC250_MERCURY`
            
        -   Lane3000 device: `EMV_LANE3000_MERCURY`
            
        -   Lane7000 device: `EMV_LANE7000_MERCURY`
            
        -   P400 device: `EMV_P400_MERCURY`
            
        -   VX805 device: `EMV_VX805_MERCURY`
            
7.  In the **Mercury Payment System** section, enter:
    
    -   **XSERVERS** - Called the IP/Hostname by Worldpay (Vantiv), enter the IP address of the computer where **NETePay** was installed.
        
    -   **COM Port** - The COM port to which the PIN pad is connected.
        
8.  Click **Save**.
    
9.  Repeat for the next workstation.
    

Important:

After configuring your RA-Workstation records, make sure your Tender in NSPOS is configured to use EMV. If you're not sure how to do this, contact NetSuite Professional Services.

Note:

Before your cashiers can use Worldpay (Vantiv) at the workstation, the setup must first sync with NetSuite. This takes about 15 minutes.

The last step is to download the software and set up your devices for EMV by following the Worldpay (Vantiv) documentation. If you're not sure how to proceed, please contact your Worldpay (Vantiv) representative.

## Worldpay (Vantiv) and EMV Receipt Requirements {#bridgehead_4586626688}

Warning:

NetSuite Professional Services must update your receipts to match EMV requirements. EMV standards include requirements for the information printed on merchant and customer receipts.

In addition to standard authorization receipt data (MerchantID, TerminalID, Clerk ID, TranCode, masked card data, CardType, Date/Time, Invoice, Reference, Amount and Total), the following EMV-specific data is required to appear on the receipt:

-   Entry Method (how card information was obtained)
    
-   Application Label
    
-   AID - Application Identifier
    
-   TVR - Terminal Verification Results
    
-   IAD - Issuer Application Data
    
-   TSI - Transaction Status Indicator
    
-   ARC - Application Response Code
    
-   CVM - Card Holder Verification Method
