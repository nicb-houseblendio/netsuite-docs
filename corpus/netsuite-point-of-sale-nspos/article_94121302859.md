In addition to behind-the-scenes fixes, NetSuite Point of Sale (NSPOS) 2024.1.0 includes the following updates.

-   **Ask for Receipt prompt appearing with Flag disabled** - Although the "Ask for receipt" flag was disabled, NSPOS might prompt a cashier to ask if shopper wants a receipt. The issue was fixed with the [Receipt Auto-print and Prompt Enhancements](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0404114749.html) feature (issue 693821).
    
-   **Customer Search Not Working If Default History Enabled** - Adding a customer to a transaction was resulting in an error if the Customer History: Include Default History flag was enabled in NSPOS. Now the cashier can search for a customer and add them to a transaction regardless of whether the flag is enabled (issue 736984).
    
-   **Gift Receipt Transaction ID & Bar Code Missing** - The bar code was not printing on gift receipts when the cashier selected to include "all items." Customers impacted by this issue should contact NetSuite Customer Support to have the fix applied (issue 723703).
    
-   **Missing Journal Entries from Duplicate Money Management Actions** - Duplicate Money Management Actions were causing journal entries to be missing in NetSuite ERP. With this fix, NetSuite ERP processes actions for specific locations before handling actions set up for empty locations. The first action is used to create the journal entry (issue 751939).
    
-   **Recount Till Form Entry Issue** - In some situations, characters entered on the recount till form were backward. Form entries now appear as expected (issue 699120).
    
-   **Rounding Differences Between Invoice and Credit Memo** - Rounding differences could occur when comparing invoices and credit memos from a sale and refund of the same item. The issue causing the rounding differences was corrected (issue 707817).
    
-   **Sales Audit Report includes NetSuite ERP Counts** - In some cases the Sales Audit report > Retail Transaction Count included transactions that occurred in NetSuite ERP. By default, the transaction count should reflect only activity performed on NSPOS workstations. The default report now excludes NetSuite ERP counts (issue 722920).
    
    ![NetSuite Transaction count option](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/Commerce/NSPOS/NetSuitePointSaleReleaseNotes/2024_1/NSPOS_Reports_SalesAudit_NS_Trans_Count.png)
-   **Sales Order Search issue from ERP Tax Amounts** - Sales orders created in NetSuite ERP with a tax amount included were not being found when searching from workstations with no NSPOS tax configuration in place.
    
    Now searches from these workstations include NetSuite ERP sales orders, but show N/A for the tax amount. The NetSuite ERP tax amount is not used at an NSPOS register because during fulfillment the workstation recalculates taxes using its local setup.
    
-   **Staging Time Outs from slow Disk Speeds** - Staging was timing-out on computers with slow disk-drive speeds, causing staging to end with an error. The time-out period has been increased to prevent this error from occurring (issue 716850).
    
-   **Synchronization issue for long Employee Email Addresses** - Email addresses longer than 64 characters for employees created in NetSuite ERP were not synchronizing with NSPOS, causing the address not to appear on NSPOS workstations. Now NSPOS can synchronize employee email address with up to 254 characters (issue 713748).
    
-   **Tax issue for Validated Returns from NetSuite ERP Sales Orders** - Instances occurred where tax was not applied as expected for a validated return of items purchased through a NetSuite ERP sales order (issue 705731).
    
-   **Text formatting for Location names in Staging app** - Long location names caused informational text in the staging application window to appear truncated or "clipped.". To provide for longer names, we removed staging **Type:** from the main staging window. Tap the **ID** and **Location** fields if you want to display the Type.
