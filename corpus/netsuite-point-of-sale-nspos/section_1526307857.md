Replication issues happen when data sync fails to exchange information between NetSuite and your registers. If a register isn't replicating data with the replication cloud, it's considered to be Offline (or Terminated).

Note:

**Item updates** - Not all fields from the item record "downsync" from NetSuite ERP to NSPOS registers. See [Item Synchronization - NetSuite ERP to NSPOS](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0614012133.html) for a list of fields that synchronize when you update an item record.

## Troubleshooting CSV Imports {#subsect_1222042948}

CSV import in NetSuite ERP is a powerful tool for updating a lot of data without manual entries. NSPOS uses SuiteScripts to properly synchronize data between NetSuite ERP and your registers. Before submitting the import, always check the **Run Server SuiteScript and Trigger Workflows** box.

In the event you submit an import without checking the "Run Server SuiiteScript..." box, use these recovery steps to resolve the issues that occur.

| CSV Import Action | Record Type | Recovery Steps |
| --- | --- | --- |
| Adding new records Editing existing records Inactivating existing records | Any affected record | Resubmit the records by either:
-   Manually opening (edit) and then saving each record, or
-   Running the CSV import again, making sure to check the **Run Server SuiteScript and Trigger Workflows** box

If you run the CSV import again, make sure you don't add new records that will override existing records you don't want changed. |
| Removing records | Most affected record types:

-   Promotions
-   Subsidiaries
-   Price Levels
-   Bar Codes
-   Gift Card types and prefixes

Other records types can be affected by this issue | After records are removed, we cannot automatically trigger their removal from NetSuite ERP. To complete the process, you must contact NetSuite Customer Support for assistance. If possible, provide Support with the record types and internal record IDs that you were removing from NetSuite ERP. |

Warning:

When updating items, prices, or other data using a CSV import, always select to **Run Server SuiteScript and Trigger Workflows**. This option triggers the processes needed for proper synchronization between NetSuite and NSPOS. See [Run Server SuiteScript and Trigger Workflows](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N355760.html#bridgehead_N356029).

## Troubleshooting Replication Issues {#subsect_7145217738}

Things like price changes not appearing on a register or customer information not updating in NetSuite ERP are clues that data synchronization isn't working at the register.

First check the workstation's status using either NetSuite ERP or NSPOS on the register. Note the last replication date. If the date isn't current as of today, replication issues exist. Contact NetSuite Customer Support for help.

![RA-Workstation terminated status](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/Commerce/NSPOS/NetSuitePointofSaleAdminGuide/NSPOS_STG_2_Terminated_Status.png)

Important:

If more than 30 days have passed since the last replication date, the register is **Terminated** and must be restaged.

Tip:

To send alerts when registers are offline, you can create a Saved Search to track register replication statuses in NetSuite ERP. These alerts can help you avoid restaging a register because it has been offline for over 30 days.

See [NSPOS Workstation Status Saved Search](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_156935954418.html#subsect_156935988072). Base the search on the date value **Last update from replication cloud**.

-   **From NetSuite ERP:**
    
    1.  Go to Customization > Lists, Records & Fields > Record Types
        
    2.  Locate the RA-Workstation row and click **List**.
        
    3.  Locate the register's RA-Workstation record and click **View**.
        
    4.  Under Monitoring, review the **Replication Status** and **Last Update** information.
        
        If a register is in an **Offline** status, you'll see a warning message.
        
        Tip:
        
        Use the **Last Update** date to determine when 30 days will have elapsed. After 30 days offline, the register is assigned a Terminated status and must be restaged.
        
    
    ![RA-Workstation offline status](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/Commerce/NSPOS/NetSuitePointofSaleAdminGuide/NSPOS_STG_2_Offline_Status.png)
-   **From the NSPOS register:**
    
    1.  Locate the **Normal State** icon in the upper left.
        
        Replication issues cause the icon to be **Amber** (Alert/warning) .
        
        ![Normal State amber alert](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/Commerce/NSPOS/NetSuitePointofSaleAdminGuide/NSPOS_Normal_State_AMBER_alert.png)
    2.  Tap the **Normal State** icon.
        
    3.  Review the **Last Update from replication cloud** panel.
        
        If the register hasn't received an update within the last hour, it is **Offline** or **Terminated**.
        
        Tip:
        
        Use the **Last Update from replication cloud** date to track if 30 days have passed. After 30 days offline, the register is assigned a Terminated status and must be restaged.
        
-   ![Normal State icon with amber color](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/Commerce/NSPOS/NetSuitePointofSaleAdminGuide/NSPOS_Normal_State_Icon.png) ![NSPOS Workstation status](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/Commerce/NSPOS/NetSuitePointofSaleAdminGuide/NSPOS_Normal_State_Wrkstation_Offline_Status.png)

## Using Reports to Identify Replication Issues by Type {#subsect_61142539811}

Applies to all current NSPOS releases.

Use these procedures to review for issues by comparing data saved to the NSPOS register with data saved in NetSuite ERP.

### If Sales/Transactions are missing in Sales Audit or Transaction Detail Reports {#subsect_13142558413}

1.  Run reports from other registers to verify if transactions are missing.
    
2.  If missing from a single register only, restart the register, wait 10 to 15 minutes and run the report again.
    
3.  Take a screenshot or notes of any errors that appear.
    
4.  Contact NetSuite Customer Support.
    

### If Sales/Transactions are missing in NetSuite ERP {#subsect_84142602677}

1.  Review the register where the transactions originated to see if an Unsent Transaction Report was created.
    
2.  Use the report to identify missing transactions and error messages.
    
3.  If possible, use the error messages to make adjustments in NetSuite.
    
4.  Contact NetSuite Customer Support.
    

Note:

You should submit separate Support cases for each error listed in the Unsent Transaction Report.

### If New or Updated Items do not appear on a Register {#subsect_91142607105}

1.  Verify if the new or updated items appear on other registers.
    
2.  If missing from a single register only, restart the register, wait 10 to 15 minutes and try again.
    
3.  Take a screenshot or notes of any errors that appear.
    
4.  Contact NetSuite Customer Support.
    

Note:

If new or changed items are missing from all registers, it could mean that there's an issue on the POS server.

### If New or Updated Tax settings do not appear on a Register {#subsect_4142611675}

1.  Verify if the settings appear on other registers.
    
2.  If missing from a single register only, restart the register, wait 10 to 15 minutes and try again.
    
3.  Take a screenshot or notes of any errors that appear.
    
4.  Contact NetSuite Customer Support.
    

Note:

If new or updated tax settings are missing from all registers, it may mean that issues are occurring on the POS server.
