This document lists the updates provided in NetSuite Point of Sale (NSPOS) version 2020.1.31. The fixes listed here are not available to NSPOS customers until they have upgraded to this version. NetSuite will modify these notes when needed to provide our customers with additional information.

## Hot Push Components {#subsect_48145208105}

This hot push is applied as an update to your NSPOS server. It is deployed automatically to customers currently on NSPOS version 2020.1.20 or later, and affects the following areas:

| Release Type | NSPOS Component | Updated? |
| --- | --- | --- |
| Hot Push | Bundle | **Yes** |
| Replication Server | **Yes** |
| NSPOS Application | **Yes** |

## Notes and Suggested Actions {#subsect_76134606264}

Updating your NSPOS components to 2020.1.31 is optional, but should be done if you have experienced any issue covered in the included fixes. Use these guidelines to decide what actions to take after the hot push is deployed to your server.

You can verify server deployment by viewing any active RA-Workstation record in NetSuite ERP. See [Appendix: NSPOS Release Types and Verification](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_86104348453.html).

### Bundle Update {#subsect_72134304055}

You must update your bundle to get the benefits included in the hot push. You can wait until time is available to do the update, but you should not delay if a fix will resolve an ongoing issue.

### Replication Server Update {#subsect_48134434021}

No user actions are available for the replication server portion of the update.

### NSPOS Application Update {#subsect_49141604975}

Some fixes in this hot push require restaging your registers/workstations. The sooner you perform restaging, the sooner your registers can benefit from the hot push.

Note that NSPOS registers can run in backward compatibility mode (one release prior to the server version) until time for restaging is available. You do not need to restage all registers immediately after the hot push is deployed.

Important:

Restaging to 2020.1.31 includes a one-time download to install MySQL 8.0.35. This portion of the staging package is around **250 MB** and may take time to complete on each register.

If a register already running 2020.1.31 must be restaged again for troubleshooting or other reasons, the staging package will not include the MySQL 8.0.35 download.

## Included Fixes {#subsect_91145539578}

The NSPOS 2020.1.31 hot push applies corrections to these issues:

-   **"Hard reset" Database Issue** - Forcing a register to shut down by long-pressing the power button was causing the MySQL database to become corrupted. A power outage could also cause this database issue to occur. Affected registers required restaging to become operational again.
    
    NSPOS 2020.1.31 includes a new version of MYSQL that prevents this "hard reset" forced-shutdown issue from affecting the database. (Issue 727153)
    
-   **Daily Tax Synchronization After Upgrade** - In rare instances, taxes were not undergoing daily synchronization from NetSuite ERP. This issue occurred after the replication server was upgraded to NSPOS 2020.1.30. (Issue 743088, 743732)
    
-   **Staging Data Errors** - Issues when generating data for the staging process could cause staging to end with errors. (Issue 739431, 741699)
    
-   **Price Changes Not Synchronizing When Certain Features Were Disabled** - When all three of these price features were disabled, price changes made in NetSuite ERP were not included in downsyncs to the server > registers (Issue 741433):
    
    -   Multiple Prices
        
    -   Quantity Pricing
        
    -   Multiple Currencies
        
-   **POS Sales Audit Report Performance** - Performance was improved for the **Credit Card by Type** field on the Sales Audit report. (Issue 740780)
    
-   **Replication Downsync Timeout** - A register connection issue was affecting replication downsync. (Issue 742809)
    
-   **MySQL Performance Configuration** - The default MySQL configuration was changed to perform better in high-demand situations. Some receipt printing issues were also fixed. (Issue 727938)
