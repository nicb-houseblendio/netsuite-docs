Note:

System Notes and System Notes v2 are two different systems. Throughout the help center, topic content specific to System Notes v2 is identified with 'v2'. Any content that doesn't have the 'v2' identification refers to System Notes only. For more information about the differences between the two systems, see [System Notes and System Notes v2](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_160225379741.html).

NetSuite uses System Notes to track any changes made to a record. A system note for a change on a record captures the date and time when the change was made, who made the change, the interface from which the change was initiated, the type of change, the field that was changed, and the old and new value in the record. System Notes can't be edited by any user, script or app. System notes are logged on both standard and custom records.

System notes are also logged on changes to general configuration settings that have a financial impact, such as:

-   Company information
    
-   General preferences
    
-   Enable features
    
-   Accounting lists
    
-   Tax setup
    

Review your system notes and audit trails regularly. As part of an Activity Logging Review, users with appropriate permission should review items like system notes in addition to reviewing specific field changes, script changes, and expired access, and any other ongoing auditing that is required by your organization.

## Accessing System Notes {#subsect_0310125020}

Depending on the method you use to access system notes, consider the following:

-   To view the system notes on a record, you must have access to this record and the Notes Tab permission. With the Notes Tab permission, you see system notes only for changes you made yourself.
    
-   To query all system notes through the analytics data source, you must have the Administrator role or the System Notes for Analytics and REST permission. Users with the Administrator role should assign this permission to users without the Administrator role so they can query system notes data. Without the Administrator role or the System Notes for Analytics and REST permission, users can see only system notes query results for changes they made themselves.
    

For more information about permissions, see [Setting Permissions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_N288727.html).

If you have access to system notes, you can view them using different methods. For more information, see [Viewing System Notes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0312034612.html).

## Searching System Notes {#subsect_0312033815}

When you search system notes, you can search for certain records, use advanced search filters, create a saved search, or export the information for additional analysis. For more information, see [Searching System Notes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N673560.html).

You can search for system notes using SuiteScript. For details, see [System Note](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1500043125.html).

## Transaction Audit Trail {#subsect_0312034237}

An audit trail is a search for system note records related to a certain record type. The Transaction Audit Trail enables you to generate a report that provides a detailed history of all transactions entered into NetSuite, or you can view system notes for multiple transactions. The audit trail shows transaction details, including who entered or modified it and when. By default, the Transaction Audit Trail report is available to the CEO, CEO (Hands Off), CFO, and Support Administrator roles. Other users with custom roles can access the Transaction Audit Trail report if they have the audit trail permission assigned to their role.

For information about transaction audit trail, see [Using the Transaction Audit Trail](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N556825.html).
