When you use SuiteCloud Development Framework (SDF) to build SuiteApps or account customizations in SuiteCloud projects, you should consider which NetSuite features your SDF custom objects require and which ones are optional:

-   For some SDF custom objects, you have to add NetSuite features to the project manifest so your SuiteApp successfully installs or your project deploys to the target account. For more information, see [Standard Feature Dependencies for SDF Custom Objects](#subsect_160823363519) and [Enhanced Feature Dependencies for SDF Custom Objects Containing OneWorld Components](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_162462756196.html).
    
-   Some SDF custom objects have optional NetSuite features, even if a record type or field depends on a feature. For those SDF custom objects, the SuiteApp installation (or SuiteCloud project deployment) succeeds, but those objects or fields that need those features won't show up for users in the target account. For more information, see [Enhanced Feature Dependencies for SDF Custom Objects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_160823364293.html).
    

## Standard Feature Dependencies for SDF Custom Objects {#subsect_160823363519}

For SDF custom objects that are not listed in [Enhanced Feature Dependencies for SDF Custom Objects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_160823364293.html) and [Enhanced Feature Dependencies for SDF Custom Objects Containing OneWorld Components](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_162462756196.html), you need to reference the feature dependencies in the SuiteCloud project so that validation and deployment succeed. This makes sure that the required features are enabled in the target account so you can use those SDF custom objects.

You reference dependencies using the `feature` element in the SuiteCloud project manifest. Each element has a `required` attribute that accepts a string value of `true` or `false`. You can update the project manifest manually or let SDF evaluate the project and update the manifest for you.

When you set a `required` element to `true`, the referenced feature has to be enabled in the target NetSuite account. Any SDF custom object in the SuiteCloud project that is feature-dependent should work as intended.

When you set a `required` element to `false`, the referenced feature doesn't need to be enabled in the target NetSuite account. Any SDF custom object in the SuiteCloud project that is feature-dependent may cause errors or warnings during validation. The element contents are ignored if they depend on features that are not required. These elements cause warnings when the SuiteCloud project is validated.

To add and define feature dependencies:

-   Using SuiteCloud Extension for Visual Studio Code, see [Adding Dependencies to the Manifest in SuiteCloud Extension for Visual Studio Code](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_160147339580.html).
    
-   Using SuiteCloud IDE plug-in for WebStorm, see [Defining Feature Dependencies in SuiteCloud IDE Plug-in for WebStorm](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1536685413.html).
    
-   Using CLI for Node.js, see [project:adddependencies](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_155981452469.html).
    
-   Using CLI for Java, see [listmissingdependencies](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4788674281.html) and [adddependencies](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4702656306.html).
    
-   Manually, see [Manually Defining Feature Dependencies in the SuiteCloud Project Manifest](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1523379149.html).
