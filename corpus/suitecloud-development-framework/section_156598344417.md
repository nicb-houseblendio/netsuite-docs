In SuiteCloud Development Framework (SDF), custom other record fields are represented by the `othercustomfield` SDF custom object. To gather information specific to your business needs, you can create different types of custom fields and apply them to your custom forms or records. Use the custom other record field in the following situations:

-   To create a more specialized custom field when the existing custom fields available in NetSuite do not fit your needs
    
-   To use on records without custom forms associated with them
    

For more information about `othercustomfield` SDF custom object, see the following topics:

-   [Setting Values on the othercustomfield SDF Custom Object](#subsect_156691673452)
    
-   [Custom Other Record Field XML Definition Examples](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_156755871736.html)
    

Note:

In the NetSuite UI, custom other field is referred to as Other Record field.

### Script ID {#subsect_156755672434}

The prefix of the custom field object's script ID should be `custrecord_`. The remainder of the ID is your choice. To enhance readability, you should create an ID that includes an underscore ( \_ ) after the custom field's prefix and adding a meaningful name after the underscore.

### Access Level {#subsect_156752260438}

The following table lists the values you can use to set access level.

| Access Level | Value |
| --- | --- |
| None | 0 |
| View Run | 1 |
| Edit | 2 |

In SDF, role access to custom other field is supported as a structured field with its own embedded structure. For more information about its supported fields and values, see [roleaccesses](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/SDFxml_2885601726.html).

This structured field is equivalent to the Role section in the following NetSuite UI:

![Other Record Field page with Access tab with Role highlighted.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteCloudDevelopmentFramework/CustOtherCustomField_Access_RoleStructuredField.png)

#### Allow Delete of List/Record Values {#subsect_156756103442}

You can use the Allow Delete of List/Record Values field when the `fieldtype` value on the custom field is set to List/Record.

The Allow Delete of List/Record Values field is represented by the `onparentdelete` element and takes the following values:

-   `NO_ACTION` - Prevent and Return Error
    
-   `_SET_NULL_` - Allow and Set Independent Values to Null
    

The following graphic shows the field and its options on the **Validation & Defaulting** subtab of the record as it appears in the NetSuite UI:

![Other Record Field page with Allow Delete of List/Record Values list highlghted on Vaidation & Defaulting tab.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteCloudCustomizationScriptingWebServices/SuiteCloudDevelopmentFramework/CustOtherCustomField_Access_onParentDeleteUIEquivalent.png)

#### Field Filter {#subsect_156756188094}

In SDF, a field filter on the `othercustomfield` SDF custom object is supported as a structured field with its own embedded structure. For more information about its supported fields and values, see [customfieldfilters](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/SDFxml_3111619060.html).

This structured field sets fields that appear on the Sourcing and Filtering subtab on other record field in the NetSuite UI.

If you change the field type or the list/record for a field that is used for sourcing or filtering on other custom fields, all sourcing and filtering based on the field is removed.

#### Translation subtab {#subsect_156756199288}

The **Translation** subtab is not currently supported by SDF. To work with translations using SDF, use the `translationcollection` SDF custom object. For more information, see [Translation Collection Object Fields in XML Definitions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1557770163.html).
