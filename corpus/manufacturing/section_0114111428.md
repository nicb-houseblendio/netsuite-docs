If you enable **classifications** such as departments and classes, a field for each classification shows in the header of transaction forms. You can also use **per-line classifications** to select a different classification on each transaction line. The following preferences can be set at Setup > Accounting > Preferences > Accounting Preferences:

-   **Allow Per-Line Departments**
    
-   **Allow Per-Line Classes**
    

For more information, see [Using Per-Line Classifications](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N265988.html).

## Class and Department Fields without Per-Line Preferences {#bridgehead_0114111654}

When you select a classification in a transaction header, all lines on that transaction use that classification. For example, if you select R&D in the **Department** field on a Work Order, all items, charges, and components on that Work Order will also use the same department.

If the department or class fields are empty in the header, they will also be empty on all transaction lines.

## Class and Department Fields with Per-Line Preferences {#bridgehead_0114111800}

When per-line preferences are enabled, **Department** and **Class** fields for transaction lines are sourced from the corresponding item, component, or charge record. For example, if these classification fields are not defined on the item record, and you create a Work Order with R&D selected in the header **Department** field, the item on that Work Order will still have an empty **Department** field.

Note:

For components, if classifications are hidden at the Work Order line level, **Department** and **Class** fields on Manufacturing posting transactions will match the transaction form header, even when per-line preferences are enabled.

All posting transactions source **Department** and **Class** information from the related Work Order.

Note:

After the Work Order is created, any changes to item, component, or charge records are not reflected on it or any posting transactions.
