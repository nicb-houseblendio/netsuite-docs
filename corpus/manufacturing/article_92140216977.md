## Manufacturing Preferences {#subsect_48140217221}

-   To help keep builds from failing, enable the [Manufacturing Preferences](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_159112709448.html) Allow Overage on Work Order Transactions option in Manufacturing Preferences and set Manufacturing Issue Based on Commitment to Limit to Committed.
    
-   Manufacturing Mobile does not support component commitment functionality.
    

## Manufacturing Mobile Preference Settings {#subsect_69140217252}

Before [Creating a Manufacturing Mobile Work Order](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_158618332264.html), make sure you configure [Manufacturing Mobile Preferences](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_164365063743.html) at an account level.

## Trigger Builds {#subsect_88140217262}

-   You should [Trigger Builds](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_164373970028.html) based on how often data needs to be pushed to NetSuite.
    
-   By default, the **Real Time Build** box is checked and enabled for all types of work orders.
    
    You can disable the real time build feature when [Creating a Manufacturing Mobile Work Order](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_158618332264.html).
    
    Note:
    
    To report data through Manufacturing Mobile, do not clear the **Real Time Build** box.
    
-   To disable default real time build for all work orders or all work orders created from sales orders, review [Manufacturing Mobile Preferences](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_164365063743.html).
    

## Backflush Work Orders {#subsect_46140217285}

-   When [Creating a Manufacturing Mobile Work Order](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_158618332264.html), you can automatically consume all work order components at the standard BOM quantities by checking the **Backflush** box.
    
    -   You can enable backflush with or without real time build and WIP work orders.
        
    -   After you check this box, you can only report production-not consumption-using the mobile scanner.
        
-   Backflush occurs at a work order level, not at a component level.
    
    If there are any serial controlled components, you cannot enable backflush.
    
-   To avoid build failures when using backflush, ensure that there is sufficient component quantity in the staging bin before you report production.
    

For more information, see the following topics:

-   [Backflush Logic](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_164251905118.html)
    
-   [Consumption with Backflush](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_164252589726.html#subsect_162136697773)
    

## Report Data {#subsect_56140217313}

-   To review common reporting and correcting scenarios, read the [Manufacturing Mobile Work Messages](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_158619942687.html) topic.
    
-   To make sure that you enter the correct finished goods costing, report consumption before you report production for non-WIP work orders.

## Over-pick Work Orders {#subsect_77140217339}

-   If you use Manufacturing Mobile with Warehouse Management, you can pick more than the quantity in the WMS app for the following work orders:
    
    -   WIP work orders with routing
        
    -   Both WIP and non-WIP work orders with work centers assigned
        
-   To enable over-picking using a mobile device for the supported work orders, configure the following:
    
    -   [Creating a WIP Bin for Manufacturing Mobile](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0622023514.html)
        
    -   [Activating the Allow Over-picking for Work Orders System Rule](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_28140403345.html)
        

## Performance Limitations {#subsect_0604114148}

-   **Backflush Component Limit**: When you backflush more than 600 components for Work in Progress (WIP) or non-WIP orders, the **MapReduce** script may time out, causing the build to fail. To prevent this issue, it is advisable to limit the number of backflush components to 600 or fewer.
    
-   **Material Consumption and Production Reporting Record Limit**: When working with nonreal-time orders, submitting a large number of material consumption or production reporting records at one time may impact the build generation process. If you submit more than 200 records at one time, the build might fail or does not generate correctly. To prevent this issue, you must submit your work periodically using the **Submit Work** button.
    
    This approach allows the records to be processed in smaller, more manageable batches and this enhances the accuracy and reliability of the build process.
