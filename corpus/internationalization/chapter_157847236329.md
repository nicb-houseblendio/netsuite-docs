You can use the record localization context in user event and client scripts to filter which scripts or workflows run.

Developers can use this feature to customize scripts for certain countries and keep them from running on records from other countries.

With localization context, the system doesn't need to load and run scripts to check if they're relevant.

Only customers using the Classic Center or Executive Center can use this feature, and it's only visible to these roles:

-   Administrator
    
-   Payroll Setup
    
-   CEO
    
-   CEO (Hands Off)
    

For more information about Centers and Roles, see [NetSuite Standard Centers](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N132466.html).

This feature also adds two new entry points for client scripts, [localizationContextEnter(scriptContext)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157495533652.html) and [localizationContextExit(scriptContext)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157495540056.html). For more information, see [Localization Context](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157496034201.html#subsect_157496046561).

For more information about entry points in SuiteScript, see [SuiteScript 2.1 Client Script Entry Points and API](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4489981198.html).
