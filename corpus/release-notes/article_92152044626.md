#### Status Indicators at the App, Task, Mobile Tab, and Record Levels {#subsect_27213423413}

New status indicators help technicians identify active sync, draft, error, and offline statuses throughout FSM Mobile.

When the app is offline, a warning banner remains at the bottom of every page as technicians move through the app. During synchronization, the active sync icon moves consistently wherever the Active Sync status appears, indicating that sync processing is in progress.

Status indicators appear in the following areas:

-   The task list shows an app-level status icon and counter.
    
-   Each task shows a task-level status icon and counter.
    
-   Mobile tabs and records show status icons that update when their statuses change.
    

The app-level counter appears at the top of the task list and shows the total number of records with active sync, draft, error, or offline status. When the app is offline, the app-level icon shows Offline, and the counter includes records pending synchronization. The task-level counter appears at the top of each task and includes only records with draft or error status.

When multiple statuses apply, each indicator shows the highest priority status at the app, task, or mobile tab level. The following priority order applies:

1.  Offline
    
2.  Active Sync
    
3.  Draft
    
4.  Error
    

#### Loading and Error Indicators on the Task List and Mobile Tabs {#subsect_2152911291}

Loading indicators help technicians identify when task data, user resources, or mobile tab data is still loading or has failed to load. Loading indicators appear on the task list and mobile tabs when the app retrieves data from the server. If loading fails, an error banner appears in the affected area.

If task data or user resources fail to load, the task list appears empty. Technicians cannot tap the **Add Tasks** button.

#### Sync Error Indicator and Retry on Records {#subsect_24205342252}

When a sync attempt fails, a dedicated error icon appears on the record to indicate that the record requires attention. Technicians can retry the sync without changing the record data, and the icon remains until the record data changes or a retry succeeds. If technicians restore the values that caused the original sync failure, the error icon may reappear.

#### Mobile Tab Details in the Navigation Bar {#subsect_30004616383}

Technicians can identify the current mobile tab and record or draft more easily because the navigation bar displays up to two lines of information. The first line always displays the configured mobile tab name. If the configured name is blank, the first line remains blank.

For an existing record, the second line displays the label and value of the first mobile tab element that provides title information. When title information is configured for a draft, the second line displays **Unsaved Draft**. If no mobile tab element provides title information, only the first line appears.

#### New cancomplete Property Controls Whether FSM Mobile Tasks Can Be Completed {#subsect_78134833817}

FSM administrators can configure the cancomplete property in the mobile event map to control task completion in the FSM Mobile app.

When `cancomplete` returns `false`, the Complete button appears dimmed. The app doesn't start a completion request.

By default, only the task assignee can complete Customer Relationship Management (CRM) tasks. Any mobile user can complete project tasks.

For other mobile event types, existing completion behavior remains unchanged unless an administrator configures `cancomplete`.

#### New create, edit, and delete Properties for Mobile Tab Permissions {#subsect_13101622403}

The `create`, `edit`, and `delete` properties control technicians' record permissions in FSM Mobile.

Each property works independently. Existing `readonly`, `min`, and `max` rules continue to apply.

This update removes the `readonly` rule from the resource level of the FSM Configuration. To align existing rules with the new `edit` property, administrators should migrate applicable `readonly` rules to the `edit` property.

Unconfigured properties and expressions that don't evaluate to true or false default to true.

#### FSM Mobile Treats Forms with Empty Elements as Complete {#subsect_88222049204}

After a mobile form closes, FSM Mobile evaluates required expressions to know if the mobile tab is complete. If an expression returns `false`, dependent mobile tabs or the **Complete** button remain available even if an empty element exists.

Previously, the app treated required expressions as `true` outside an open form. An empty element could cause the app to treat the mobile tab as incomplete.

#### Automatically Map NetSuite Fields for an FSM Mobile Tab {#subsect_77085049436}

In the FSM configuration, administrators can set a mobile tab's `automap` property to `true`. This setting maps elements automatically, so administrators don't need to define each corresponding field in `article.map`.

FSM maps an element at runtime when its ID exactly matches a field ID on the record specified by `article.record`. Existing explicit mappings take precedence, and the `automap` property doesn't modify the FSM Configuration.

Before setting `automap` to `true`, confirm that each element ID matches an existing NetSuite field ID. A mismatch can cause the mobile tab request to fail and prevent tasks from loading in FSM Mobile. For more information, see [Automatic Mapping of NetSuite Fields for an FSM Mobile Tab](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0810081531.html).

#### Heading Blocks Organize Mobile Tabs {#subsect_64235704169}

Administrators can organize long mobile forms with static heading blocks. This feature eliminates the need for placeholder fields or inline HTML workarounds.

To add a heading, an administrator configures a mobile tab element with the `heading` block type and a `label`. The `level` property supports values 1, 2, and 3, in decreasing order of visual prominence. An invalid level value defaults to 1.

Each heading spans the full content width and follows the existing element-ordering logic. The `index` property controls the position when defined. Otherwise, FSM Mobile uses the element order. Although heading blocks affect the layout, the mobile app excludes heading blocks from the save payload. For more information, see [Adding Heading Blocks to Field Service Management Mobile Tabs](https://suiteanswers.custhelp.com/app/answers/detail/a_id/1046936) (SuiteAnswers ID 1046936).

#### Mobile Expressions Include Date and Time Helpers {#subsect_30184452545}

FSM Mobile expressions include `format(date)` and `now()` helpers for configuring date, time, and datetime values without custom formatting logic. These helpers work in mobile expressions, including dynamic resource block properties such as `min`, `max`, and `value`.

FSM automatically migrates existing `nxc_now()` expressions to the corresponding helper replacements while preserving existing checkbox conditions. FSM stores the migrated expressions in a copied configuration record named **Auto Configure xxxx: Migrate nxc\_now expressions**.

For more information, see [Date, Time, and Datetime Values for FSM Mobile Elements](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0805103802.html).

#### Configure Track Service Time in FSM {#subsect_80232937978}

Administrators manage the Track Service Time feature through the Boolean `time.timetracking` FSM configuration option. The option controls whether the feature is enabled. Accounts that had Track Service Time enabled before the update retain the setting. Before enabling the feature in production for the first time, administrators must test it in a sandbox account.

For more information, see [Enabling the Track Service Time Feature](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_0801120413.html).

#### Use Saved Searches to Monitor FSM Mobile User Licenses {#subsect_13055114804}

Employee records no longer display current and total mobile license counts beside the **Field Service Mobile User** field. To monitor mobile license usage, administrators must create a saved search and compare its results with the **Field Service Management Users** row on the Billing Information page.

To open the Billing Information page, go to _Setup > Company > View Billing Information_.

For more information, see [Creating a Saved Search to Monitor Field Service Mobile User Count](https://suiteanswers.custhelp.com/app/answers/detail/a_id/1046924) (SuiteAnswers ID 1046924).

#### Portuguese Locale Available in the FSM Mobile App {#subsect_15015701287}

FSM Mobile supports Portuguese (Portugal) through the `pt_PT` locale, displayed as Português (Portugal). Translations are available only for accounts in Portugal with Portuguese (Portugal) set as the default language.

#### Searchable Select Fields Reset in New Table Rows {#subsect_91095801453}

A searchable select field in a new table row opens with an empty search field and unfiltered options. Previously, the field could retain search text and filtered options from the previous row.

#### Select Fields Display the Selected Option Label {#subsect_14052437960}

A select field with a saved value displays the label of the matching option when the form reopens. If no matching option exists, the field displays the saved-value label. Previously, the field could display the saved-value label instead of the label from the current option list.

#### Search Remains Open When Returning to a Mobile Tab {#subsect_80155041120}

When you return to a mobile tab with a saved search keyword, the search field opens automatically with that keyword, and the list remains filtered. Previously, the keyword could remain saved while the search field remained closed. On mobile tabs without remote search, the mobile app did not apply the saved filter until the search field reopened.

#### Task List Search Text Persists After Reloading the Mobile Tab {#subsect_35094700913}

After the app is refreshed or reopened, the task list search field displays the saved search text. The task list remains filtered by that text. Previously, the task list could remain filtered while the search field appeared empty.

#### Service Report Images Display for Additional Customer Languages {#subsect_5180924353}

Images linked to completed tasks and project tasks display on Service Reports regardless of the customer's **Field Service Language**. Previously, images could be omitted when the selected language was not English or French.

### Sync and Error Indicator Improvements in FSM Mobile App {#subsect_59152313661}

The FSM mobile app includes the following updates to sync and error indicators:

-   The task list and individual tasks display clearer loading, syncing, and error indicators. Individual tasks show loading, syncing, and error icons, and the task list displays an error banner when task data can't be loaded.
    
-   The map displays an error indicator when the initial map load fails or when task map routes can't be loaded. This indicator lets technicians know that the displayed map may be incomplete or inaccurate. The indicator doesn't appear if a subsequent map reload fails after the initial map load succeeds.
    
-   Remote select and multiselect fields display a searching status while data loads and an error message when the data can't be loaded. This makes the request status clearer during remote fetches.
    
-   Images display a loading indicator while image previews load. If an image preview can't be loaded, the mobile app displays an error indicator. This helps technicians understand whether an image preview is still loading or unavailable.
    
-   The mobile app displays a warning when technicians tap the Refresh icon or the Log Out button while unsynced data is present. This warning helps prevent accidental data loss.

-   **Text Areas No Longer Resize in the FSM Mobile App**
    
    Text area fields in the FSM mobile app are no longer resizable. Previously, resize behavior could differ by platform, and text areas weren't resizable on iOS devices.
    
-   **Mobile App Accepts Email Addresses with Special Characters**
    
    When you click Mobile Login in the employee record, the mobile app loads correctly for employee email addresses that contain special characters, including the plus (+) symbol. Previously, the mobile app could fail to load and display an error.

### Default Translations Added for NetSuite-Supported Languages in FSM {#subsect_87152444480}

The SuiteApp includes translations for all languages that NetSuite supports. The translation collection includes default translated strings, so you don't need to manually import strings for the standard product. The collection is locked and overwrites existing strings. If you previously modified the collection in your NetSuite account, add the custom strings again by following the process in the help topic [Multi-Language Support for FSM](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_1021030703.html).

The collection includes only English (US) strings, and FSM uses for all English languages. The collection doesn't include separate strings for other English variants.

### Enhanced Permissions for Field Service Roles {#subsect_82152448161}

The following Field Service Management roles get additional permissions to improve access control:

| Role | Subtab | Permissions | Level |
| --- | --- | --- | --- |
| Field Service System | Transactions | Charge | Full |
| Setup | Custom Fields | View |
| Setup | Custom Record Types | View |
| Lists | Record Custom Field | View |
| Transactions | Purchase Order | Full |
| Field Service Administrator | Setup | Translation | Full |

The Field Service Manager and Field Service Administrator roles now have the **Field Service Mobile** and **Field Service Scheduler** boxes checked by default. These permissions give access to mobile and scheduling features.

These updates help administrators improve role configuration and user access control.

### Task List Search and Filter Enhancements in Mobile App {#subsect_81152453820}

A new search filter is available at the top of the mobile task list, letting you quickly filter tasks. As you enter text, the task list updates in real time to show matching results. The filter supports clear, persistent filtering and shows a message when there are no matching tasks.

This enhancement streamlines finding tasks and improve the overall mobile user experience. The filter applies to all task and event data loaded on the mobile app.

### Barcode Scanning from the Search Option in FSM Mobile {#subsect_73152457982}

On FSM Mobile tabs with a search option in the page header, a barcode scanner icon appears next to the search option when your device camera is available. After you grant camera access, scanning a barcode replaces any existing search text and uses the same search and filter behavior to show matching records. For example, on the **Assets Installed** tab, you can scan an asset barcode to quickly find existing asset records.

### Task List Fetching and Loading Indicators Updated in FSM Mobile {#subsect_15152503638}

The FSM Mobile app includes the following updates to task list fetching and loading indicators:

-   The task list view shows a loading icon during the initial task search and displays a message in your selected language when no tasks exist. The loading icon is different from the sync icon to help you distinguish between loading and syncing.
    
-   The **Add New Task** button stays dimmed until all required data is available and remains disabled if the data fails to load.
    

### Issue Fixes {#subsect_28152508731}

-   **Improved Dropdown Performance for Large Lists in FSM Mobile**
    
    FSM Mobile displays dropdown options faster by loading only the items you can see on screen, which reduces delays for lists with up to about 80,000 items. Dropdown search and filter behavior stays the same, including on the **Inventory** tab.
    
-   **Project Task Fields Show Previously Saved Field Values When Show Project in New UI Preference Is Set**
    
    If the **Show Project in New UI** box is checked on the General Preferences page, you'll see the previously saved field values when you edit an existing project task. Previously, all fields appeared blank when editing an existing project task.
    
-   **Faster Responses for Field Service Suitelet API Requests**
    
    Field Service Suitelet API requests return responses faster. Previously, an unnecessary translation check added delays to unrelated requests.
    
-   **Activity Time Records Generate for Completed Tasks Even When Other Tasks Have Processing Errors**
    
    When the Time Tracking feature is enabled, the Time Scheduled script continues processing other tasks if one task encounters an error. The script skips the failed task for 24 hours and then retries it. If the failed task is recovered earlier, it returns to the queue the next time the Time Scheduled script runs.
    
-   **FSM Mobile Task Status Based on Field Service Start and Field Service End Fields**
    
    FSM Mobile determines task status based on the **Field Service Start** (custevent\_nx\_task\_start) and **Field Service End** (custevent\_nx\_task\_end) fields, as follows:
    
    -   **Not Started** - Displays when both fields are blank.
        
    -   **In Progress** - Displays when only the **Field Service Start** is set.
        
    -   **Completed** - Displays when the **Field Service End** is set.
        
    
    The mobile app ignores the task status value in NetSuite. If you change the task status in the NetSuite user interface, you must clear these fields using a workflow, script, or manual process to ensure the status in FSM Mobile remains synchronized.
    
    To learn how to clear the **Field Service Start** and **Field Service End** fields manually, see [Updating the FSM Mobile Task Status from the NetSuite User Interface](https://suiteanswers.custhelp.com/app/answers/detail/a_id/1045621) (SuiteAnswers ID: 1045621).
    
-   **Independent Resizing for Preview and Editor Fields on the Field Service Configuration Page**
    
    When the Configuration Preview feature is enabled, you can resize the **Preview** and **Editor** fields independently on the Field Service Configuration page. Previously, when you edited a Field Service Configuration record, you couldn't read, scroll, or resize the **Editor** and **Preview** fields.
    
-   **Remote Search Returns Results for Select Fields in Table Rows**
    
    Fields configured for remote search in table row forms now return matching options even when the parent table uses a remote configuration. This update restores the expected behavior for fields such as the **Item** field on the **Quote** and **Order** tabs.
    
-   **Restored Hourly Scheduling for Field Service Scheduled Script**
    
    The Field Service Scheduled Script now runs hourly throughout the day. This change ensures uninterrupted operation of FSM processes that rely on hourly script scheduling.
    
-   **Complete Visibility for Address Search Suggestions in Asset Form**
    
    The full dropdown menu for the address search field displays correctly when the field is in the leftmost column of an Asset form. Suggested addresses are no longer cut off, ensuring all results are visible and accessible.
    
-   **Update Status Banner Appears When There Are Pending Updates**
    
    The Update Status banner appears only when there are pending updates for the case or its child tasks. Previously, the banner appeared even when the case didn't need any updates.
    
-   **Custom Form Labels Use Account's Default Language in FSM Mobile**
    
    FSM Mobile displays custom form field labels for all configured fields based on the language selected in the employee record's **Field Service Language** field. If this field is blank, the app uses the account's default language. Previously, in accounts with a default language that isn't English, FSM Mobile displayed default field labels instead of custom form labels.
    
-   **Email Notifications Send When HTML Title Includes Multiple Lines**
    
    The system sends email notifications even if the HTML template title contains multiple lines. Previously, the system couldn't send email notifications when the title had multiple lines.
    
-   **Field Service Icon Appears in Browser Tab**
    
    The FSM Schedule Board now displays the Field Service icon on the browser tab. This update fixes the incorrect file path error.
    
-   **Status on Agenda Task Cards Updates When You Return to the List Page**
    
    After you start or complete a task in FSM Mobile, the status badge on the Agenda task card shows the current status as soon as you return to the list. Previously, the task card shows the old status until you changed the search filter.

### Issue Fixes {#subsect_32152750412}

-   **Improved Barcode Scanning Reliability**
    
    The barcode scanner in FSM Mobile more consistently reads and captures barcode values, even in less ideal lighting or camera angles. The scanner automatically selects the optimal resolution for your device, improving overall scanning accuracy and performance across all supported barcode types.
    
-   **Fixed CSV Import for Employee Passwords**
