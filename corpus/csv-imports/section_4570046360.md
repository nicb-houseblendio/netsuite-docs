This section describes errors that you might see on a vendor payment import. See the following:

-   [Invalid account reference key Accounts Payable xx for entity xx](#bridgehead_4570047725)
    
-   [Unable to find a matching line for sublist apply with key: \[doc,line\]](#bridgehead_4570048068)
    
-   [One or more bills or invoices has had a payment made on it since you retrieved the form](#bridgehead_4570050086)
    
-   [Adding new line to sublist apply is not allowed](#bridgehead_4570050581)
    
-   [Unparseable Internal Id, did you mean to lookup this field by Name or External ID? for field xx](#bridgehead_4570051095)
    

## Invalid account reference key Accounts Payable xx for entity xx {#bridgehead_4570047725}

The Accounts Payable account listed on the _Transactions > Payables > Pay Bills_

If you use the internal ID to map the bill to be paid, you do not need to map the Accounts Payable account since the system will search for the bill and then in turn encounter the applicable AP account for the bill.

To resolve the error, remove the AP account from the field mapping.

## Unable to find a matching line for sublist apply with key: \[doc,line\] {#bridgehead_4570048068}

The error can occur when you're importing new customer or vendor payments and there are no open invoices with the internal ID or external ID specified in the CSV file.

In this situation you need to verify if:

-   The payments being imported are applied to invoices that are open and not already paid with a status of Paid in Full.
    
-   The internal ID or external ID specified in the CSV file corresponds to an existing open invoice in the system.
    

You can search for invoices by external ID or internal ID. These are the only reference fields you can use to import vendor or customer payments, so make sure your CSV uses either the internal ID or external ID of the bill.

Try one or more of these steps to check the invoice status and fix the error.

## Use a Saved Search {#bridgehead_4570048548}

To create a saved search that uses the external ID or internal ID of the invoice as a filter:

1.  Go to _Lists > Search > Saved Searches_ > New.
    
2.  Click **Transaction**.
    
3.  On the Criteria > Standard subtab, add Internal Id (Number **) to use the internal ID of the invoice. You can also enter the external ID as a filter**.
    
4.  Click **Save and Run**. Look for the invoice and check its status.
    

## Use the Invoice List {#bridgehead_4570048783}

If you know the internal ID of the invoice you want to verify, look for the invoice on the invoice list.

To use the invoice list:

1.  Go to _Home > Set Preferences_ > General.
    
2.  Check **Show Internal Ids and save**.
    
3.  Go to _Transactions > Sales > Create Invoices_ > List. Look for the invoice and check its status.
    

## Use Accept Customer Payments {#bridgehead_4570049124}

1.  Go to _Transactions > Customers > Accept Customer Payments_.
    
2.  In the **Customer field, enter the name of the customer**.
    
3.  Select the correct A/R account. Only open invoices appear on the Apply > Invoices subtab.
    

## Use Vendor Bill Payments {#bridgehead_4570049341}

1.  Go to _Home > Set Preferences_ > General.
    
2.  Check **Show Internal Ids and save**.
    
3.  Go to Transactions > Purchases/Vendors > Enter Bills > List. Look for the bill and check its status.
    

## Use Pay Single Vendor {#bridgehead_4570049562}

1.  Go to Transactions > Purchases/Vendors > Pay Single Vendor.
    
2.  Enter the name of the Vendor in the **Payee field**.
    
3.  Select the correct A/P account. Notice only open Bills appear on the Apply subtab.
    

## Use Pay Bills {#bridgehead_4570049771}

1.  Go to Transactions > Purchases/Vendors > Pay Bills.
    
2.  Select the correct A/P Account. Only open bills appear on the Apply subtab.
    

## One or more bills or invoices has had a payment made on it since you retrieved the form {#bridgehead_4570050086}

The error usually occurs when the vendor bill has a term and a discount amount.

To resolve, consider the following:

-   Update the CSV import file. Payment amount should be equal to the actual payment amount due, that is, the net amount (Amount - Discount Amount = Payment Amount Due).
    
-   If there should not be a discount on the vendor bills, update the bill records and clear out the Terms and Disc. Amt. fields.
    

Note:

This error also applies when importing customer payments.

## Adding new line to sublist apply is not allowed {#bridgehead_4570050581}

This error happens when you try to import vendor payments and apply existing vendor credits at the same time. Also, the following conditions apply.

-   Vendor credits are already posted in NetSuite, and the CSV file contains the following fields:
    
    -   External ID
        
    -   Vendor ID
        
    -   Payment Amount
        
    -   ID of the Bill
        
-   The Payment Amount for the vendor bill is positive and for the bill credit the amount is negative.
    
-   The Vendor Bill Credit Internal ID and the Vendor Bill Internal ID are used on the ID of the Bill column.
    

The error will be encountered if:

-   Data Handling is set to **Add. Set it to** **Add/Update**.
    
-   The **Vendor Bill is no longer Open or has already been paid with status Paid in Full**.
    
-   The Bill Credit has already been applied.
    
-   The Vendor Bill **and** Bill Credit do not have the same A/P Account.
    

## Unparseable Internal Id, did you mean to lookup this field by Name or External ID? for field xx {#bridgehead_4570051095}

The xx in the error message refers to the mapped field name in the CSV file.

The value you mapped to the NetSuite field Bill (Req) couldn't be found. Make sure it matches the internal ID of the bill being paid. You can get the internal ID from the bill's URL or by running a saved bill search that includes the internal ID column.
