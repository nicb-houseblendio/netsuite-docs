On a pick task subrecord, you can view failures that may occur because of inventory changes or order updates that coincide with item fulfillment generation. Issues may also occur when released orders are fulfilled directly from an order transaction or when item fulfillments are manually created outside of the wave.

Instead of viewing pick tasks one at a time, you can create a pick task saved search. The results of this saved search includes a list of pick task lines with quantities, status, and failures. For more information, see [Viewing, Updating, or Deleting Pick Tasks](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1548082148.html).

On pick task lines with failed fulfillments, you can view the failure reason and handle the errors accordingly. You have the following options to handle fulfillment creation failures:

-   **Retry Updates** to try to generate the item fulfillment again after you resolve issues described on the failed lines.
    
-   **Override Fulfillment Creation** to cancel fulfillment generation through the pick task and directly create one from the order or through bulk fulfillment. .
    
-   **Reverse Picks** to return picked quantities, which sets the pick task line to **Done** status.
    

To view issues for a fulfillment generation job, see [Viewing the Status of Fulfillment Generation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1541442979.html).

If you have bins with insufficient quantity, you can look for related transactions for the same item that may affect available quantity in a bin. For information about managing inventory levels, see [Assessing Stock Levels](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2262573.html) and [Reviewing Negative Inventory](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2268458.html).
