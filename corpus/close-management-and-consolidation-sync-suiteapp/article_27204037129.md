For every saved search you can filter data by how long ago it was created or last updated. For metadata saved searches, you can also customize the hierarchy of metadata you want to export in a saved search.

#### To customize a saved search:

1.  In NetSuite, go to NetSuite EPM > Close Management and Consolidation > Manage Saved Searches.
    
    NetSuite displays a list of saved searches.
    
2.  Click **Customize** next to a saved search of your choice.
    
    If you've already customized the saved search, the **Edit** button is available for you to make any additional changes.
    
3.  Under the Add-On Filter section, from the **Filter** list, select one from the following options:
    
    -   **No Filter**
        
    -   **Created or Updated Since N Days Ago**
        
    -   **Created Since N Days Ago**
        
    
    Where **N** is the number of days in the past to include in the filtering. Specify the number in the **Days** field.
    
    Note:
    
    This filtering doesn't modify the configuration of the created saved searches. It only filters the results of saved searches executed in your Financial Consolidation and Close.
    
4.  If you're customizing a metadata saved search, take any of the actions under the Hierarchy Settings section. Some of the actions may not be applicable to the metadata saved search you're customizing:
    
    1.  Enter a value in the **Top Level Parent Value** field to customize the top level parent name.
        
    2.  To create your own hierarchy for the metadata saved search, select the column you want to use as the parent from the **Alternate Parent Column** list. The default value is **Not Set**. You can only choose from columns you've added to the saved search with a unique Custom Label value. See step 8 in [Creating the Hierarchy of Metadata in Close Management and Consolidation Sync](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_64133705355.html).
        
        If you select an alternate parent column, you can expect the following behavior:
        
        -   If you've added columns to the metadata saved search result, the values of the columns are populated with values from one of their children.
            
        -   To import the saved search result correctly to your Financial Consolidation and Close, make sure the alternate parent column has a unique value for each item.
            
        -   If you remove any predefined column from the metadata saved search result, the saved search output may not be generated properly.
            
        -   If your preferred language differs from your account's default language, the alternate parent column may not be used when generating the alternate metadata hierarchy.
            
    3.  If you need to run an Import Data/Metadata job with this saved search, and the selected alternate parent column doesn't have a corresponding counterpart in your Financial Consolidation and Close, check the **Exclude Alternate Parent Column** box. This excludes the alternate parent column from the CSV file that will be uploaded to your Financial Consolidation and Close. If you don't exclude the column, the generated saved search result won't be imported successfully to your Financial Consolidation and Close.
        
        Note:
        
        You can't exclude required columns, for example, the Data Storage column. If you attempt to exclude a required column, Close Management and Consolidation Sync ignores the fact that you've checked the box. To exclude the alternate parent column from the CSV file that will be uploaded to your Financial Consolidation and Close, check the **Exclude Alternate Parent Column** box.
        
    4.  Check the **Exclude Upper Level Hierarchy Members** box, if you don't want to include the upper level member in the hierarchy. This option applies only to the Accounts and Item metadata saved searches.
        
    5.  Enter a value in the **Category Prefix** field to customize the default category prefix. Make sure the category prefix is unique for each metadata saved search.
        
    6.  To skip running the default metadata saved search and use only data from the customized search, check the **Return Hierarchy Based Only on Data in This Search** box. For details, see [Returning Metadata Hierarchy Based Only on Cloned Saved Search in Close Management and Consolidation Sync](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_35133742085.html).
        
5.  If you're customizing a metadata saved search, take any of the following actions under the Parent Level Transaction section. Some of the actions may not be applicable to the metadata saved search you're customizing:
    
    1.  From the **Data Storage for Parent Record** list, select the default value for the Data Storage column in the exported metadata saved searches:
        
        -   **Never Share** - This option sets the value of the Data Storage column for the parent to Never Share.
            
        -   **Dynamic Calc** - This option sets the value of the Data Storage column for the parent to Dynamic Calc.
            
        -   **Store** - This option sets the value of the Data Storage column for the parent to Store.
            
        -   **Store/Never Share** - When the parent has only one child, Close Management and Consolidation Sync sets the value of the Data Storage column to **Never Share**. Otherwise, the value is set to **Store**. Also, when you select this option, Close Management and Consolidation Sync doesn't let you set any filter under the Add-On Filter section.
            
        
        Your selection impacts the way data is stored and calculated for the parent in your Financial Consolidation and Close.
        
        Note:
        
        The default value of the Data Storage column for all child records in all the supported metadata hierarchies is **Store**.
        
    2.  To change the default prefix or suffix for the member name, do the following:
        
        1.  Enter a value in the **Member Name Affix Value** field.
            
        2.  From the **Custom Affix for Member Name** list, select whether you want to add **Member Name Affix Value** as **Prefix** or **Suffix**.
            
            If you select the **Use Default** option, the default **P\_** prefix is used.
            
    3.  To change the default prefix or suffix for the alias column, do the following:
        
        1.  Enter a value in the **Alias Affix Value** field.
            
        2.  From the **Custom Affix for Alias** list, select whether you want to add **Alias Affix Value** as **Prefix** or **Suffix**.
            
            If you select the **Use Default** option, the default **Total\_** prefix is used.
            
6.  Under the Sorting section, from the **Sort By** list, select the required option for sorting metadata in the saved search result:
    
    -   Sort metadata alphabetically by **Alias**.
        
    -   Sort metadata numerically by **Member Internal ID**.
        
    -   Sort metadata alphabetically by **Member Name**.
        
    
    If you don't select any sorting option, the metadata is automatically sorted by **Member Internal ID**.
    
    Metadata is sorted on each level of the hierarchy.
    
7.  Under the Alternate Saved Search section, from the **Alternate Saved Search Name** list, select a saved search to substitute for the original saved search. Close Management and Consolidation Sync executes this saved search every time the original saved search is called from Data Exchange.
    
    If you select an alternate saved search, you can expect the following behavior:
    
    -   The settings of the alternate saved search override the original saved search settings.
        
    -   The alternate saved search is ignored when running a saved search for an Import Data/Metadata job.
        
    
    If you use the default **Not Set** value, the original saved search is executed.
    
8.  Click **Save**.
