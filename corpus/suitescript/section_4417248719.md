Here's the basic process flow for creating a SuiteScript 2.1 script. For a more detailed explanation with a sample script, check out [SuiteScript 2.1 Hello World](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1503717063.html). If you want to see a diagram of a valid script's structure, see [SuiteScript 2.1 Anatomy of a Script](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1510274310.html).

| Stage | Description | Additional Information |
| --- | --- | --- |
| 1 | Use the `define()` function to load modules in your entry point script. This is the script you attach to the script record. | [Modular Architecture](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1508957818.html) [SuiteScript 2.1 Global Objects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387171685.html) |
| 2 | Add the required JSDoc tags to your entry point script. | [SuiteScript 2.1 JSDoc Validation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387175355.html) |
| 3 | Add at least one entry point function to your script. An entry point function is a named function that runs when an entry point is triggered. Important: Your entry point script can only use one script type. For example, it can't return both a `beforeLoad` entry point and an `onRequest` entry point. | [SuiteScript 2.1 Script Types](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387172495.html) |
| 4 | Organize your supporting code into custom modules (instead of SuiteScript 1.0 libraries). Create these modules with the `define()` function, then load them in your entry point script. | [SuiteScript 2.1 Global Objects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387171685.html) |
| 5 | Upload and deploy your script to NetSuite. | [SuiteScript 2.x Entry Point Script Creation and Deployment](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4525001447.html) |
