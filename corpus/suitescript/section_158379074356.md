SuiteScript scripts run on either the client's browser or the NetSuite server. There is one client script type and several server script types, including map/reduce, mass update, and more.

The documentation for each SuiteScript module indicates whether module members can be used in a client script, a server script, or both.

## Client Scripts {#subsect_158473831107}

Client scripts affect how and what type of data is shown on a NetSuite page. It is deployed either on a single record, on multiple records, or on a form. A client script can run any time the user accesses a specific record or a specific form, such as creating a new record or updating an existing record. A client script can also run as the page is loaded into the browser, any time the user enters or updates data on the page, and when the user submits the page. The client script is one of the most commonly used script types. For more information, see [SuiteScript 2.1 Client Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387798404.html).

## Server Scripts {#subsect_158473833814}

Server scripts provide general data processing based on script type:

| Server Script Type | Purpose | Additional Information |
| --- | --- | --- |
| Map/Reduce | Map/reduce scripts process large amounts of data across one or more records in stages using the map/reduce paradigm. The map/reduce script can be executed on demand or on a predetermined schedule. | [SuiteScript 2.1 Map/Reduce Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799161.html) |
| Mass Update | Mass update scripts perform custom updates to record fields that are not available through general mass updates. Mass/update scripts are executed on demand only using the Perform Update button on the Mass Update Results Preview page; they cannot be automatically executed based on a deployment or schedule. . | [SuiteScript 2.1 Mass Update Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4460452911.html) |
| Portlet | Portlet scrips are used to display a custom portlet on a user's dashboard. Portlet scripts run on the server and are rendered on the user's browser. | [SuiteScript 2.1 Portlet Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799288.html) [Dashboard Portlets](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N576951.html) |
| RESTlet | RESTlets are used to import data into NetSuite or export data from NetSuite. A RESTlet is called from an external application or from within NetSuite. | [SuiteScript 2.1 RESTlet Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799403.html) |
| Scheduled | Scheduled scripts perform actions based on a specific schedule. Scheduled scripts can be executed on demand or in the future according to a schedule, and can be set to run on a recurring basis. | [SuiteScript 2.1 Scheduled Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799491.html) |
| Suitelet | Suitelets are used to create custom NetSuite pages and perform backend processing. Suitelets are typically executed when an `http.get` or `http.put` request is received. | [SuiteScript 2.1 Suitelet Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799600.html) |
| User Event | The user event script is one of the most commonly used script types. It can be used to perform processing, such as:
-   Determine what data is displayed on the NetSuite page in the user's browser and how it is displayed.
-   Determine what data is returned to another requesting server script, a web services client (for example, SOAP or REST), or a CSV import.
-   Validate user data and process data written to the database.

A user event script can be deployed on a single record or on multiple records and is executed any time the record is created, loaded, copied, deleted, or submitted. | [SuiteScript 2.1 User Event Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799721.html) |
| Workflow Action | Used to create custom workflow actions. | [SuiteScript 2.1 Workflow Action Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4460429314.html) [SuiteFlow (Workflow)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/book_N2723865.html) |

Two additional server script types are available but are only executed when installing a bundle or SuiteCloud project. These script types can perform actions or tasks (setup, configuration, and data management tasks) typically performed by an administrator. The main difference between the two script types is where and how they are deployed.

-   The bundle installation script is used to perform actions before or after a bundle is installed or updated, or before the bundle is uninstalled. Bundle installation scripts are included in a bundle and are deployed as part of the bundle. See [SuiteScript 2.1 Bundle Installation Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4460460309.html) for more information about the bundle installation script.
    
-   The SDF installation script is used to perform actions during the deployment of a SuiteApp from SuiteCloud Development Framework (SDF). An SDF installation script can be incorporated into a SuiteApp deployment, or a SuiteApp project can include an SDF installation script that is automatically executed when the SuiteApp is deployed. See [SuiteScript 2.1 SDF Installation Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1544719586.html) for more information SDF installation scripts.
