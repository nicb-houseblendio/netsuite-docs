| **Enum Description** | This holds the string values for user event execution contexts. The beforeLoad, beforeSubmit, and afterSubmit entry points use `context.type`, which takes one of the enum values. Note: JavaScript doesn't have a built-in enumeration type. When SuiteScript 2.1 docs say "enum," they mean a plain object where each key maps to a read-only string value. |
| --- | --- |
| **Module** | [SuiteScript 2.1 User Event Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799721.html) |
| **Since** | Version 2015 Release 2 |

## Values {#bridgehead_4407994847}

| 
-   APPROVE
-   CANCEL
-   CHANGEPASSWORD Note: The CHANGEPASSWORD user event runs when a user updates their NetSuite password in the UI. That event only appears in the NetSuite account where the password was changed.
-   COPY
-   CREATE
-   DELETE
-   DROPSHIP
-   EDIT
-   EDITFORECAST
-   EMAIL
-   MARKCOMPLETE
-   ORDERITEMS
-   PACK
-   PAYBILLS
-   PRINT
-   QUICKVIEW
-   REASSIGN
-   REJECT
-   SHIP
-   SPECIALORDER
-   TRANSFORM
-   VIEW
-   XEDIT

Note: There's no execution context for VOID actions, so it isn't a supported user event context. When a transaction is voided, scripts set to run on EDIT might still trigger on VOID, but may not work as expected. To avoid issues, add conditions in your EDIT scripts to filter out transactions where the memo is "Void" or "Voided," and check for the voided field. See [Catch the Void Using a User Event Script](https://suiteanswers.custhelp.com/app/answers/detail/a_id/68789) for details. |
| --- |

For an example of the context.UserEventType, see [SuiteScript 2.1 User Event Script Sample](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799721.html#bridgehead_4485602565).

Note:

If you attach or detach a child custom record from its parent, it triggers an edit event.
