Use the N/currentRecord module to access the record that is active in the current client context. This module is always a dynamic object and mode of work is always dynamic, not deferred dynamic/standard. For more information, see [SuiteScript 2.x Standard and Dynamic Modes](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1524156901.html). Be aware that when the current record is in view mode it cannot be edited; it is a read-only record when in view mode. As such, any set APIs do not work on the current record in view mode.

**[N/currentRecord Module Script Samples](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0302071622.html)**

You can use the currentRecord module in the following types of scripts:

-   **Entry point client scripts** - These scripts use the `@NScriptType ClientScript` annotation. (For details, see [SuiteScript 2.1 JSDoc Validation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387175355.html).) The system automatically provides this type of script with a [currentRecord.CurrentRecord](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4642657958.html) object that represents the current record. For this reason, an entry point client script does not have to explicitly load the N/currentRecord module. To access the currentRecord object, create a variable and initialize it to the value of the `scriptContext.currentRecord` property, which is available in each of the [SuiteScript 2.1 Client Script Entry Points and API](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4489981198.html). For an example, see [SuiteScript Client Script Sample](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/bridgehead_4484779426.html).
    
-   **Client custom modules** - These scripts do not use an `@NScriptType` annotation (see [SuiteScript 2.1 Custom Modules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4704097697.html)). For these scripts, you must manually load the N/currentRecord module by naming it in the script's define statement. Additionally, you must actively retrieve a [currentRecord.CurrentRecord](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4642657958.html) object by using the [currentRecord.get()](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4637729624.html) or [currentRecord.get.promise()](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4637734729.html) method. For an example, see [N/currentRecord Module Script Samples](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0302071622.html).
    

Like the [N/record Module](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267255811.html), the currentRecord module provides access to body and sublist fields. However, you should use the record module for server scripts and for cases where a client script needs to interact with a record other than the currently active record. You should use the currentRecord module for client scripts that need to interact with the currently active record.

Additionally, the functionality of the two modules varies slightly. For example, the currentRecord module does not permit the editing of subrecords, although subrecords can be retrieved in view mode. For additional details, see the following topics:

Refer also to [SuiteScript Supported Records](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_N3170023.html).
