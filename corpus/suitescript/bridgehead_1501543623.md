## SuiteScript Versions {#bridgehead_161849369316}

The sample script uses SuiteScript 2.1, the latest SuiteScript version. It supports newer ECMAScript language features.

For help writing scripts in SuiteScript, see [SuiteScript 2.x Entry Point Script Creation and Deployment](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4525001447.html).

## SuiteScript Reserved Words {#bridgehead_158687949169}

Like most programming languages, SuiteScript has a list of reserved words you can't use as variable or function names in your scripts. For example, `var` is used to declare a variable, and `try` marks the start of a try-catch block. For more information, see [SuiteScript Reserved Words](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_158687368641.html).

## SuiteScript 2.1 Script Types and Entry Points {#bridgehead_1501609217}

Before you start writing your script, you need to pick which predefined **script type** to use. Each script type is made for certain situations and specific triggering events. The following are some of the available [SuiteScript 2.1 Script Types](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387172495.html):

-   The [SuiteScript 2.1 Client Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387798404.html) is for scripts that should run in the browser.
    
-   The [SuiteScript 2.1 Scheduled Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799491.html) is for server scripts that should run at a specific time or on a recurring schedule.
    
-   The [SuiteScript 2.1 RESTlet Script Type](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387799403.html) is for server scripts that should run when called over HTTP by an application external to NetSuite.
    

Each script type has one or more **entry points** unique to that type. An entry point is where the system hands control of NetSuite to your script. When you add an entry point to your script, you're telling the system to do something when that entry point is triggered. This runs a function in your script, called an **entry point function**.

For many script types, entry points are like events, or the different things that can happen, to trigger your script. For example, client script entry points are events that can happen in a browser session, like [fieldChanged(scriptContext)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4410692508.html) when a field value changes, or [pageInit(scriptContext)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4410597671.html) when a page loads. In contrast, the scheduled script type has only one entry point, called [execute](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4407979858.html). This is when a schedule runs the script or a user runs it manually.

In the example in this tutorial, you want a dialog alert to pop up when someone loads the NetSuite task record page in a browser. So, this example uses the client script type and the pageInit entry point.

## SuiteScript 2.1 Modules {#bridgehead_1501609041}

SuiteScript 2.1 uses [Modular Architecture](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1508957818.html). All its APIs are organized into standard modules, and each module's name shows what it does. For example, the [N/record Module](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267255811.html) lets you work with NetSuite records, whereas [N/https Module](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4418229131.html) lets you make HTTPS requests to external web services.

Most modules need to be loaded in your script before you can use their APIs. Loading a JavaScript module is like importing a library in Java. It gives you access to code that's defined somewhere else. In an entry point script, you load modules through the [define Object](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4387811519.html). You list the modules you want to load as arguments.

Some APIs are globally available, so you can use them without loading their modules first. You'll find a list of these globally available APIs in [SuiteScript 2.1 Global Objects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4387171685.html).

The example in this tutorial uses both: some globally available APIs, and a method that only works after you load the right module.

## Entry Point Scripts vs. Custom Module Scripts {#bridgehead_1503446283}

The example script includes everything in one file. But sometimes you'll want scripts that use logic from other files. In SuiteScript, these extra files are called **custom module scripts**.

The main script file-the one that sets the script type, entry point, and entry point function-is called an **entry point script**. Entry point scripts have their own formatting rules, which are different from custom module scripts. The next steps in this tutorial point out some of these requirements.

This topic doesn't cover custom module scripts. For more on those, see [SuiteScript 2.1 Custom Modules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4704097697.html).
