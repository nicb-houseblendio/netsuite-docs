When you create, copy, load, or transform records in SuiteScript, you can work with records in standard or dynamic mode.

**Standard mode:**

When a SuiteScript 2.x script creates, copies, loads, or transforms a record in standard mode, the record's body fields and sublist line items are not sourced, calculated, and validated until the record is saved with [Record.save(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267286323.html). You might also see this referred to as "deferred dynamic mode" in the SuiteScript help.

When you work with a record in standard mode, in most cases, you don't need to set values in any particular order. When you submit the record, NetSuite will process the fields and sublist items in the right order, no matter how your script is organized. See [Getting Text in SuiteScript 2.x Record Modes](#bridgehead_1524158225).

**Dynamic mode:**

When a SuiteScript 2.x script creates, copies, loads, or transforms a record in dynamic mode, the record's body fields and sublist line items are sourced, calculated, and validated in real time. Dynamic mode makes the record behave like it would in the NetSuite UI.

Note:

In dynamic mode, the Legacy Tax field **Tax Code** isn't automatically transferred when a requisition becomes a purchase order. For more information, see **[Tax Code Limitations When Using SuiteScript 2.x](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0616101140.html)**.

In dynamic mode, the order of setting field values is important. This might feel limiting to some developers. You'll probably need to check the UI often when scripting in dynamic mode. For instance, when creating an invoice in the UI, you wouldn't set the Terms field before the Customer field. That's because setting the Customer field will override the Terms field value. On an invoice, the value of Terms is sourced from the terms specified on the Customer record. This behavior also applies to dynamic scripting. If you don't set field values in the right order in your script, some values might get overridden.

**How you can tell if a record is in dynamic mode:**

You can determine if a record is in dynamic mode using these two SuiteScript 2.x properties:

-   [Record.isDynamic](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4296707316.html) (for server scripts)
    
-   [CurrentRecord.isDynamic](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4637576809.html) (for client scripts)
    

## Record Modes and User Event Scripts {#bridgehead_1524158046}

User event scripts that use newRecord or oldRecord objects always run in standard mode. This is why you might see the SSS\_INVALID\_API\_USAGE error in these situations:

-   When the user event script executes on a record that is being created, and the script attempts to use [Record.getText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273156769.html) without first using [Record.setText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273157034.html) for the same field.
    
-   When the user event script executes on an existing record or on a record being created through copying, and the script uses [Record.setValue(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273155868.html) on a field before using [Record.getText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273156769.html) for the same field.
    

## Getting Text in SuiteScript 2.x Record Modes {#bridgehead_1524158225}

In dynamic mode, you can use [Record.getText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273156769.html) without limitation, but in standard mode, there are some limits. In standard mode, you can use this method **only** in these situations:

-   You can use [Record.getText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273156769.html) on any field where the script has already used [Record.setText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273157034.html).
    
-   If you are loading or copying a record, you can use [Record.getText(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273156769.html) on any field except those where the script has already changed the value with [Record.setValue(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4273155868.html).
    

## Record Module Method Considerations {#bridgehead_1524167531}

Be aware that the [record.create(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267258059.html), [record.copy(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267258260.html), [record.load(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267258486.html), and [record.transform(options)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4267258715.html) methods work in standard mode by default. To use these methods in dynamic mode, set the `.isDynamic` property for each one.
