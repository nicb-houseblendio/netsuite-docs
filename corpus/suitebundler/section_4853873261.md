The NetSuite application is accessible in different types of accounts. These different account types serve different purposes. Support varies for bundle operations across the different account types. See the following for details:

-   [Account Types that Support Bundles](#bridgehead_4853894813)
    
-   [Support for Bundle Install and Update Across Account Types](#bridgehead_4853897363)
    
-   [Support for Bundle Copy and Push Across Account Types](#bridgehead_4853898447)
    
-   [Support for Managed Bundle Upgrade Across Account Types](#bridgehead_4853898874)
    
-   [Support for Bundle Search Across Account Types](#bridgehead_4853899135)
    

## Account Types that Support Bundles {#bridgehead_4853894813}

-   Production
    
    The production (or live) account is where users do the daily work necessary to run their business. See [The Production Account](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_1121105140.html).
    
-   Sandbox Accounts
    
    A NetSuite sandbox is an isolated account where you can develop new processes and applications. The data in the sandbox is a copy of your production data. You can update your sandbox data to match your production data at any time. See [NetSuite Sandbox](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_N333400.html).
    
    The URLs that customers use to access this type of sandbox account are the same as the URLs they use to access their production accounts, for example, https://system.netsuite.com. Users access sandbox accounts from the Change Roles list in the production account.
    
-   Development Accounts
    
    Development accounts are spaces isolated from production for testing and developing new apps and customizations. Development accounts have the same features and modules as your production account, but they do not contain production data. Unlike sandboxes, development accounts don't get updated with new data. See [NetSuite Development Accounts](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4422375565.html) or [SuiteApp Development Process with SuiteBundler](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_4444212213.html).
    
-   Release Preview
    
    You can try out Release Preview twice a year, before each new release. Use Release Preview to test how new features will work with your daily business processes. Release Preview data is a snapshot of your production data at a certain point in time. See _The Release Preview Environment_ and [Release Preview Guide](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/preface_4019941373.html).
    
    You access Release Preview accounts using the same URL as your production account, for example, https://system.netsuite.com. To get to Release Preview, just switch roles from the Change Roles list in the production account.
    

## Support for Bundle Install and Update Across Account Types {#bridgehead_4853897363}

The following table illustrates support for bundle installation and update across account types.

|  | **BUNDLE TARGET** |
| --- | --- |
| **Production** | **Development Accounts** | **Sandbox Accounts** | **Release Preview** |
| **BUNDLE** **SOURCE** | **Production** | Yes | Yes | Yes | Yes |
| **Development Accounts** | Yes | Yes | Yes | Yes |
| **Sandbox Accounts** | Yes | Yes | Yes | Yes |
| **Release Preview** | No | No | No | Yes |

For information about installing a bundle, see [Installing a Bundle](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3395142.html).

For information about updating a bundle, see [Installed Bundle Updates](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3397927.html).

For information about sandbox refresh impact on bundles, see [Sandbox Refresh Impact on Bundles](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3405932.html).

## Support for Bundle Copy and Push Across Account Types {#bridgehead_4853898447}

You can copy a customization bundle from one account to another. Copying bundles is related to deprecating them - you can replace an old bundle with a new one.

-   You can only copy bundles between production and development accounts. Bundle copying isn't available for account types other than production or development.
    
-   For information about copying a bundle, see [Copying a Bundle to Other Accounts](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3391248.html).
    

As a bundle author, you can push your bundles to accounts where you're an administrator. This enables NetSuite resellers and independent software vendors to install bundles without having to log in to each of their customers' accounts.

-   Bundle push is only supported for production accounts and development accounts. You cannot push a bundle from or to any type of account other than production or development.
    
-   For information about pushing a bundle, see [Pushing a Bundle to Other Accounts](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3391992.html).
    

## Support for Managed Bundle Upgrade Across Account Types {#bridgehead_4853898874}

When a managed bundle is installed, the installer agrees to subscribe to future updates at the discretion of the bundle's author. As updates are developed, they can be installed by the bundle author into the target accounts without any action required by the target account administrator. See [Managed Bundles Overview](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3382953.html) and [Upgrading Your Managed Bundle Install Base](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3383724.html).

The following table illustrates support for managed bundle upgrade across account types. The term 'Manual' indicates that an automated upgrade initiated by the bundle author is not supported, but a target account user can initiate a manual upgrade.

|  | **BUNDLE TARGET** |
| --- | --- |
| **Production** | **Development Accounts** | **Sandbox Accounts** | **Release Preview** |
| **BUNDLE** **SOURCE** | **Production** | Yes | Yes | Manual | Manual |
| **Development Accounts** | Yes | Yes | Manual | Manual |
| **Sandbox Accounts** | No | No | No | No |
| **Release Preview** | No | No | No | No |

## Support for Bundle Search Across Account Types {#bridgehead_4853899135}

The Search & Install Bundles page, available at _Customization > SuiteBundler > Search & Install Bundles_, includes the following two search modes. See [Bundle Searches Overview](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N3394713.html).

-   Basic mode: a simple way to search for bundles across all production locations.
    
-   Advanced mode: a more detailed search with extra filters.
    

The following table illustrates support for the two bundle search modes across account types.

|  | **WHERE SEARCH IS PERFORMED** |
| --- | --- |
| **Production** | **Development Accounts** | **Sandbox Accounts** | **Release Preview** |
| **WHERE BUNDLE WAS CREATED** | **Production** | Basic Advanced | Basic Advanced | Basic Advanced | Basic Advanced |
| **Development Accounts** | Basic Advanced | Basic Advanced | Basic Advanced | Basic Advanced |
| **Sandbox Accounts** | Advanced | Advanced | Advanced | Advanced |
| **Release Preview** | No | No | No | Basic Advanced |
