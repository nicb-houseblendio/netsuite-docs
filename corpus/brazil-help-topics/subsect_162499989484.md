Note:

To access the Brazil Certification Tax Authorities SuiteApp documentation in Brazilian Portuguese (Português do Brasil), see [Brazil Certification Tax Authorities](https://system.netsuite.com/help/helpcenter/shared_resources/PDF/BrazilCertificationTaxAuthorities_pt_BR.pdf).

When using the Brazil Certification Tax Authorities SuiteApp, keep in mind the following limitations:

-   E-documents certified in the test environments of certain tax authorities display some default return information.
    
    In the e-document certification return records for these e-documents, the certified e-document number is always 000. The certification date is the date and time at which the e-document is sent for certification. NetSuite populates the fields by default because the tax authorities don't return valid certification data in their test environments. The default information prevents possible errors.
    
    The tax authorities are São Paulo (SP) and those that use the DSF standard.
    
-   XSD validation is available only for the sending operations of selected tax authorities.
    
    The availability of XSD validation depends on the tax authorities usage of XSD files themselves. For more information about XSD validation for Brazil, see [Predefined E-Document Validation Files for Brazil](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_163283858825.html).
    
-   The receiver acknowledgment feature requires the [Brazil Localization](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_164002729517.html) SuiteApp.
    
-   The capture of incoming e-documents is subject to the limitations imposed by the Secretaria da Fazenda. For example, the national environment's web service only returns e-document operations performed in the last 3 months.
