Sections are used to store document content and further organize information within groups. For example, a document for a configurable desk may include a group for desk materials. Within that group, there may be:

-   A section to introduce the materials.
    
-   A table listing the materials.
    
-   A closing section to explain the manufacturing process.
    

You can create multiple sections within a group. To sort sections, use the sequence number. Sections with a lower number are placed higher within the parent group.

To include or exclude sections in a document, use rules with question and answer combinations from configured items. For more information about rules, see [Activating or Hiding Building Blocks with Rules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_4124359628.html).

A section can contain text or a table. You can customize text sections using HTML and CSS code. In text section, you can also include dynamic information using resolve expressions and placeholders. For more information, see [Including Dynamic Information in Text Sections](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8163432400.html).

Table sections may be introduced by text. Some tables can source item data from transaction line fields (**Item List Table** option). The table will include default columns corresponding to the following resources:

-   Line number
    
-   Item name/number
    
-   Rate
    
-   Quantity
    
-   Amount
    

Alternatively, table sections can source data from configured items (**Table** option). Data is sourced from answers or predefined answers that store an array of JSON objects. For example, you may create a table section sourcing content from the predefined answer that stores the list of additional items. Answers that can store arrays are input box text fields and text areas. For more information, see [Input Box Questions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0726121124.html#subsect_0727094151) and [Predefined Answers for Configuration Information Storing JSON Objects](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_8171845565.html#subsect_0418105423).

Note:

Use CSS code to style the tables.

The section type you can choose depends on its purpose, frequency, and the frequency of the parent group. The following table sums up the available section types and the options you can select.

| Section Usage | Group Record | Section Record |
| --- | --- | --- |
| Repeat Field | Type Field | Run For Field |
| --- | --- | --- |
| Single text section | Once | HTML | \- |
| Text section repeated for every configured item | Every Item | HTML | Configured Items |
| Text section repeated for every additional item | Every Item | HTML | Generic items |
| Text section repeated for every line item | Every Item | HTML | All Items |
| Introductory text section at the beginning of a grouping by field value | Every Item | HTML | Item Group Header |
| Closing text section at the end of a grouping by field value | Every Item | HTML | Item Group Footer |
| Text section repeated for every configuration | Every Config | HTML | \- |
| Single table section with item data from transaction line fields | Once | Item List Table | \- |
| Table section with configured item data repeated for every configured item | Every Item | Table | Configured Items |
| Table section with configured item data repeated for every configuration | Every Config | Table | \- |

#### To create a section:

1.  On a saved group record, go to the **Sections** subtab.
    
2.  Click **New CPQP Section**.
    
3.  Provide a descriptive name for the section.
    
4.  Provide a sequence number to sort this section within the group.
    
    Enter a negative or positive number, for example, -2 or 5.
    
5.  Select the section type.
    
6.  If the section type is **HTML**, enter the text in the **HTML Content** field.
    
    You can format the text by changing the paragraph font and size or making the text bold, italic, or underlined. You can also customize the content with HTML code and inline CSS. Click the **Source** button to access the HTML editor.
    
    Note:
    
    If the section type is **Table** or **Item List Table**, you can still enter text in the **HTML Content** field. This content will appear before the table.
    
7.  If the section type is **Item List Table** and you want to include transaction fields other than the default ones, specify the transaction line fields that will become the table columns. In the **Table Column Mapping** field, enter the field IDs and assign them labels. This is the syntax:
    
                    `[    {       "fieldID1":"label1"    },    {       "fieldID2":"label2"    },    {       "fieldID3":"label3"    } ]` 
                  
    
8.  If the section type is **Table**, specify where the array of JSON objects is stored and the JSON properties that will become the table columns.
    
    1.  In the **Table Form QA** field, provide the predefined answer or the answer that stores the array of JSON objects. Enter the question and answer codes separated by a forward slash. For example, SOLE/MATERIALS or Q/A.
        
    2.  In the **Table Column Mapping** field, enter the JSON properties to be used as columns and assign them labels. This is the syntax:
        
                            `[    {       "property1":"label"    },    {       "property2":"label"    },    {       "property3":"label"    } ]` 
                          
        
    
    For example, a configurable desk includes a desk mat, a lamp, and an organizer as additional items. You can create a table using the SOLE/ITEMS predefined answer. This predefined answer stores the list of the additional items as an array of JSON objects.
    
    Let's say you want the table to include the following JSON properties:
    
    -   `itemname` (**Name** field)
        
    -   `price`
        
    -   `qty`
        
    
    In the **Table Column Mapping** field, you can enter the following code:
    
                    `[    {       "itemname":"Additional Item"    },    {       "price":"Price"    },    {       "qty":"Quantity"    } ]` 
                  
    
    Suppose a customer selected all three additional items. If you added basic formatting, the table on the final document would look like this.
    
    | Additional Item | Price | Quantity |
    | --- | --- | --- |
    | Desk Mat | 50 | 1 |
    | Lamp | 30 | 1 |
    | Organizer | 20 | 1 |
    
9.  If the parent group repeats for every line item, select the line items for which you want to repeat the section in the **Run For** field.
    
    The following options are available:
    
    -   **Configured Items** - Repeats the section for every main configured line item on the transaction. Additional items are excluded.
        
    -   **Generic Items** - Repeats the section for every additional line item on the transaction.
        
    -   **All Items** - Repeats the section for all line items on the transaction: configured, additional, and manually added line items.
        
    -   **Item Group Header** and **Item Group Footer** - When items are grouped by field value, these options repeat the section one time at the beginning or at the end of each grouping.
        
        For more information about grouping line items, see [Grouping Line Items](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_6135420618.html#subsect_0714052656).
        
10.  In the **Show Rule** field,provide the condition that determines whether the section will be included in the final document.
     
     The condition is based on question and answer combinations from a NetSuite CPQ product. Enter question and answer codes separated by the forward slash character. For example, A/1. Use operators to combine multiple conditions. For example, A/1&B/2. For more information, see [Activating or Hiding Building Blocks with Rules](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_4124359628.html).
     
11.  Click **Save**.
