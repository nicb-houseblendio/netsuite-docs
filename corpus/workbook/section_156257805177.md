## SuiteQL Performance and Best Practices for Connect {#subsect_156330163819}

You can improve query performance by following guidelines and best practices. These guidelines apply even if a SuiteQL is later transformed to SQL by a process hidden to the user.

You should consider the following tips for optimal query performance:

### Testing Queries {#subsect_0204034809}

Evaluate the performance of the query after it is written. If the performance of the query is not ideal, you should experiment with query simplification or by replacing with semantically equivalent notation with better performance.

### Syntax and Performance Best Practices {#subsect_0204034908}

As you create queries using SuiteQL and the Connect Service, you must follow specific SuiteQL syntax requirements and best practices. For more information, see [SuiteQL Performance and Best Practices](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_0824094533.html).

### Multiple Connections {#subsect_0204035034}

Running multiple concurrent sessions can slow performance and the retrieval of results. For information about running multiple connections when working with SuiteAnalytics Connect, see [Multiple Concurrent Sessions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4153627846.html#subsect_162091936102).

### Roles and permissions {#subsect_0204035205}

Roles and restrictions can result in performance issues. Ensure that you apply the necessary access restrictions for human interaction and consider adapting the access restrictions for automated machine-to-machine transfers. For more information about roles and permissions, see [Connect Permissions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_3998867068.html).

### Oracle SQL {#subsect_0204035323}

Due to Oracle SQL syntax working internally with NetSuite Analytics, you should use Oracle SQL syntax when creating SuiteQL queries. Although SuiteQL supports ANSI SQL-92, there's a risk of critical performance issues, such as time outs that aren't operationally remediable, that may occur if a SuiteQL is converted to SQL. This approach helps avoid the worst performance scenario, regardless of other factors. The following example shows how you can change your queries to use Oracle SQL syntax.

-   The following query doesn't follow the Oracle SQL syntax:
    
                      `select t.id, t.period, t.amount, a.name, p.name from transaction t join account a on a.id = t.account left outer join accountingperiod p on p.id = t.period` 
                    
    
-   The following query follows the Oracle SQL syntax:
    
                      `select t.id, t.period, t.amount, a.name, p.name from transaction t, account a, accountingperiod p where a.id = t.account and on p.id(+) = t.period` 
                    
    
-   Note that you can't use right outer joins in Oracle syntax. You can use ANSI syntax for outer joins. For example, the following Oracle SQL is not valid in SuiteQL:
    
                      `select a1.id from account a1, account a2 where a1.id (+) = a2.id` 
                    
    

## Querying the Analytics Data Source {#subsect_156330165432}

To find all record types and fields that are currently available for the analytics data source schema, see [Record Types and Fields](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_164312261929.html).

The analytics data source isn't accessible for some roles and permissions. For more information, see [Role and Permission Considerations for NetSuite2.com](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/subsect_162885566786.html).

## Unsupported Features in SQL-92 {#subsect_156330284269}

When using SQL-92 syntax, there are several features that aren't supported, including embedded null values in `CHAR` fields, `DEFAULT` clauses for column values, and subqueries in `SELECT` lists.

## Supported and Unsupported Functions {#subsect_43123143092}

There are several functions that you can use when you run queries using SuiteQL. For a full list of supported and unsupported functions, see [SuiteQL Supported and Unsupported Functions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_158513731864.html).

## Supported Built-in Functions {#subsect_50123256369}

You can use built-in functions to perform certain operations in SuiteQL queries. For a full list of supported built-in functions, see [SuiteQL Supported Built-in Functions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/article_161950565221.html).
