Create a payment run when you want to group payable transactions and prepare payments from a single workflow.

Make sure you have access to create payment runs and select the paying account. Eligible payable transactions should already exist.

## Payment Run Validation {#subsect_1145327664}

Payment run validation includes the following behavior:

-   You can't save a payment run when the total payment run amount is not positive.
    
-   You cannot save a payment run when the total payment amount is zero or negative. NetSuite displays a Record Not Saved message indicating that the total must be positive.
    
-   Credits can reduce the run total, so users should review the Summary panel before saving.
    

#### To create a payment run:

1.  Go to Transactions > Payables > Enter Payment Run > List.
    
2.  On the Payment Runs list, select New.
    
3.  In Account, select the bank, cash, or credit card account to use for the payments. The selected account determines the Payment Run Currency. The Account also determines the Payment Run Subsidiary.
    
4.  Confirm the populated account details, such as currency, balance, available balance, and subsidiary.
    
5.  In Payment Date, enter the date for the payment run.
    
6.  In Posting Period, select the accounting period for the run.
    
7.  Enter any required classification values, such as class or location.
    
8.  Add transactions to the run. Payment runs support vendor bills, vendor credits, qualifying journal entry lines, expense reports, and bill payments with a remaining negative amount. NetSuite adds selected transactions and recalculates the summary.
    
    Warning:
    
    A payable already included in another incomplete payment run can't be used in another payment run. This also applies to installments and transactions added through SuiteScript. Rejected, cancelled, and failed lines that have been released may be available again for other payment runs depending on their payable status.
    
    If you attempt to pay or offset an included payable through a bill payment, NetSuite warns that the transaction is already in a payment run. You can continue, but the payment run line for that payable may later fail if the payable becomes unavailable or its amount due changes.
    
    1.  In the payment run, go to the Transactions subtab.
        
    2.  Click Add Transactions.
        
    3.  In the Add Transactions window, search or filter the list of eligible transactions.
        
        Note:
        
        Payment runs can also include open or partially paid installments when the **Installments** feature is enabled.
        
        Each eligible installment appears as a separate row in **Add Transactions** with a read-only Installment Number. Users select the required installment and can change its Payment amount. The selected installment then appears as a separate payment run line.
        
    4.  Use filters such as Payee, Type, Currency, A/P Account, or Due Date to narrow the list.
        
    5.  Click the checkbox for each transaction you want to include.
        
    6.  Review the Payment amount for each selected transaction.
        
    7.  Click Add.
        
    8.  Review the transactions added to the payment run and the Summary panel before saving.
        
9.  Save the payment run.
    

NetSuite saves the payment run and assigns a payment run number. Depending on your approval configuration, the run may need approval before payments can be created.

Note:

Credits can reduce the total amount of the run. The total payment run amount must be positive before you can save the run.

Note:

Discounts are handled as follows: The Discount Available depends on the Payment Date and discount terms. Discount Taken cannot be negative or exceed the Discount Available amount. Partial-payment discounts are calculated proportionally, and changing the Payment Date recalculates the applicable discount and summary.

Tip:

If the transaction you need is not listed, confirm that it is eligible for payment and matches the account, currency, subsidiary, and filter criteria.
