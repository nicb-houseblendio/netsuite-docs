The workflow execution log is a system-generated log that tracks all actions and transitions that run on a record for a specific state visit in a workflow. You can use the workflow execution log to debug and troubleshoot the workflow execution for a record. For example, you can use the log to determine which actions and transitions in a workflow did or didn't run.

If a workflow button appears but doesn't run the expected transition, review the workflow execution log and Workflow History. Check whether the **Add Button** action ran during record load. Then check whether a transition moved the record to another state.

To access the workflow execution log, select the record that the workflow instance ran on, and click the **System Information** subtab. On the **System Information** subtab, click the **Workflow History** subtab, then click **Log** for the state you want to view. NetSuite displays all log entries for the selected state visit in a new window.

You can use the workflow execution log to view the following types of information:

-   [Server Triggers](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4471794948.html)
    
-   [Event Types and Contexts](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4471795340.html)
    
-   [Action and Transitions Status](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4471795732.html)
    
-   [Evaluation of Conditions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4471796153.html)
    
-   [Rejected Actions and Transitions](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4471796522.html)
    

**Tip:** If a button appears on a record but is no longer valid, review the server trigger sequence. Check the Add Button action status, transition conditions, and transitions that ran during the same state visit.

For example, a workflow execution log can show that an **Add Button** action executed on **Before Record Load** and that a condition-based transition also executed during the same processing cycle. In this case, the form may display the button that was added earlier, even though the workflow has already moved to another state.

Note:

If the overall workflow execution fails, SuiteFlow rolls back any changes made by the actions in the workflow. However, the actions will still appear in the log.
