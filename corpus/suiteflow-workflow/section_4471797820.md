The following screenshot shows the workflow execution log for a Bike Repair workflow that executed on a custom record and entered a state called Entry on an After Record Submit trigger:

![A portion of the workflow execution log for a Bike Repair workflow that executed on a custom record and entered a state called Entry on an After Record Submit trigger.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteFlowWorkflow/BikeRepairActionsNotExecuteLog.png)

The execution log shows the following information about the workflow:

-   The workflow initiated on this record.
    
-   The entry trigger, ONENTRY, ran. In addition, the initiation trigger for the workflow is After Record Submit: `Running ONENTRY trigger under AFTERSUBMIT`.
    
-   A Send Email action executed but the workflow skipped the other Send Email action.
    
-   A Set Field Value action executed.
    
-   The Exit trigger, ONEXIT, executed.
    

## Issues with the Workflow {#bridgehead_4448306341}

Although two actions did run, the workflow state contains many more actions. The other actions didn't run because of the server trigger on which the record entered the state.

The following screenshot shows a portion of the **Workflow State** window and the two actions that executed:

![A portion of the Workflow State window with the two actions that executed highlighted: Send Email and Set Field Value.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteFlowWorkflow/BikeRepairActionsNotExecuteActionsList.png)

The following screenshot shows the initiation trigger type for the workflow:

![A portion of the workflow definition page showing the settings in the Basic Information, Initiation, and Event Definition sections. The Trigger Type field is highlighted with the After Record Submit trigger type selected.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteFlowWorkflow/BikeRepairActionsNotExecuteActionsWF.png)

Because the workflow initiated on an After Record Submit trigger, the record entered the state on an After Record Submit trigger, and the following issues occurred:

-   The Send Email and Set Field Value actions executed because they were valid actions for a state with an After Record Submit trigger.
    
-   The other Send Email action failed, even though it was set to process on an After Record Submit trigger, because it required the Service Manager field to be set. However, the Service Manager field wasn't set because the action that set the value didn't run because of its trigger: Before Record Submit.
    

This workflow doesn't initiate until after the data on the record is written to the database. Consequently, any action set to run before the data is written to the database doesn't run. In this example, only actions with an After Record Submit, Entry, or Exit trigger run.

The following screenshot shows the original configuration of the Set Field Value action:

![Screenshot with the Set Field Value settings highlighted.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteFlowWorkflow/BikeRepairActionsNotExecuteActionsList2.png)

## Solution {#bridgehead_4448306222}

To make sure that the Send Email action to the Service Manager completes, complete one of the following two tasks:

-   Change the workflow initiation trigger type to All or Before Record Submit. Consequently, any of the Before Record Submit actions will run.
    
-   Change the trigger type of the Set Field Value action to After Record Submit. Since the workflow initiates on an After Record Submit trigger, the Set Field Value action will run.
    

The following screenshot shows the workflow execution log after the trigger type for Set Field Value action is changed to After Record Submit:

![A portion of the workflow execution log after the trigger type for the Set Field Value action is changed to After Record Submit.](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/img/SuiteFlowWorkflow/BikeRepairActionsNotExecuteLogSuccess.png)

After changing the trigger type for Set Field Value action to After Record Submit, the workflow execution log shows that the Set Field Value and Send Email actions, which didn't process before, now run properly.
