The following features are only available in a limited form in sandbox accounts:

| Feature | Testing Notes |
| --- | --- |
| Alternative Payment Methods | No actions taken (no payment sent). Test mode is on for all payment processing profiles. |
| Credit Card Processing | Real credit card numbers are not copied. They are replaced with test numbers; for example, 1111111111111117. To create billing processes or credit card processing for testing in your sandbox, use only test credit card numbers and a valid expiration date. Important: See [Credit Card Processing in Your Sandbox After a Refresh](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1516027026.html) for more information. |
| Direct Deposit | No actions taken. |
| Map/Reduce Scripts Scheduled Map/Reduce Scripts | Scripts scheduled in production are copied to sandbox accounts, but are not scheduled by default. You can set them to Scheduled after your sandbox refresh is activated. For details, see [Scheduled Script Execution](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4664470832.html). |
| NetSuite Connector | You cannot connect multiple NetSuite accounts (production, sandbox, Release Preview) to the same NetSuite Connector account. You can only connect one NetSuite account to a NetSuite Connector account at a time. For more information, see [General NetSuite Connector FAQ](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_164025511298.html) and [Checking Accounts for NetSuite Connector Deployment](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_163004074146.html). |
| PayPal Integration | No actions taken. |
| Perquest | No actions taken. |
| SAML Single Sign-on | SAML configuration is not copied from the production account to the sandbox account. You must configure SAML in your sandbox account after each refresh. |
| Scheduled SuiteScripts | Scripts scheduled in production are disabled by default in sandbox accounts, but you can set them up and test them. For details, see [Scheduled Script Execution](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4664470832.html). |
| SSN or TIN (Social Security Number or Tax Identification Number) | Real numbers not copied. Use only test numbers. |
| Token-based Authentication | Tokens created using the Token-based Authentication feature in your NetSuite production account are not copied to your sandbox account. To test this feature, you must create tokens in that sandbox account. Each time your sandbox is refreshed, you must create new tokens in that sandbox account. |
| UPS/FedEx Integration for Shipping Labels | No actions taken. |
| Website and Web Store | Websites that exist in your production account are copied to your sandbox, but you must set up domains after a refresh. Domains are not copied from your production account to your sandbox account. After a sandbox refresh, you must set up domains in the sandbox account. See [Automatic and Manual Certificates](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_157538985860.html) and [Set Up Domains for Web Stores](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2484898.html) for more information. Note: If you have multiple sandbox accounts, ensure that the domains are unique across all of your accounts. An error message is generated if there are duplicate domains. Websites created only in your sandbox account are lost after a sandbox refresh, and need to be recreated. For more information, see [Getting Started](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2655840.html). |
