You can only create one rebate preferences record per payment type.

#### To set the rebate preferences:

1.  Go to Rebate Management > Preferences > Preferences > New.
    
2.  Select or enter the required information in the fields described in the following table.
    
    | **Field Group** | **Description** |
    | --- | --- |
    | **Payment Type** | This field is required.
    -   **Paying**\- Choose Paying if you are paying rebates.
    -   **Receiving**\- Choose Receiving if you are receiving rebates.
    
     |
    | **Transaction Type** | **Sale**\- Sales transactions include sales orders, invoices, returns, and cash sales. This transaction type is selected by default. **Purchase**\- Purchase transactions include purchase orders, vendor bills, vendor credits, and vendor returns. |
    | **Customers** | The values displayed on the lists are sourced from the customer record. **Customer Inclusions**\- Select a maximum of five customer attributes. **Customer Exclusions**\- (Optional) Select a maximum of two customer attributes. The system sources the customer criteria shown on the agreement details based on the values you select from each Customer Inclusions and Exclusions lists. You can also create a List/Record type custom field to have additional options for customer criteria selection. See [Creating a Custom Field](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2829580.html). The custom field you add displays on the Agreement Details subtab of a rebate agreement. Note: The custom field does not display if you deactivate, edit the agreement details, then reactivate the field later. Edit the Agreement Details record only after reactivating the custom field then saving the changes. |
    | **Vendors** | The values displayed on the lists are sourced from the vendor record. **Vendor Inclusions**\- Select a maximum of five vendor attributes. **Vendor Exclusions**\- (Optional) Select a maximum of two vendor attributes. The system sources the vendor criteria shown on the agreement details based on the values you select from each Vendor Inclusions and Exclusions lists. You can also create a List/Record type custom field to have additional options for vendor criteria selection. See, [Creating a Custom Field](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2829580.html). |
    | **Items** | The values displayed on the lists are sourced from the item record. **Item Inclusions**\- Select a maximum of five item attributes. The system sources the item attributes from the inclusion criteria you select in the agreement details. **Item Exclusions**\- (Optional) Select a maximum of two item attributes. The system sources the item attributes from the exclusion criteria you select on the agreement details. Similar to the customer custom field, you can also create a List/Record type custom field for items to have additional options for item criteria selection. See [Creating a Custom Field](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2829580.html). Note: To include a particular subsidiary and exclude another subsidiary from the same parent company, select the Subsidiary or Primary Subsidiary in both the inclusions and exclusions list. |
    | **Apply Best Deal** | Select the condition for how you want the system to select and apply the best deal rebate for an item.
    
    -   **Minimum Rebate**\- Select Minimum Rebate for the system to apply the lowest rebate value on the item.
    -   **Maximum Rebate**\- Select Maximum Rebate for the system to apply the highest rebate value on the item. The Maximum Rebate preference is selected by default.
    
    Important: After you set the Apply Best Deal preference and save the record, you can't edit it later. |
    | **Accounting** | This field shows the list of posting and non-posting accounts available in the system.
    
    -   When receiving rebates, select an account for the accrual expense and the accrual receivable accounts: You must not use an A/P control account or an A/R control account when posting accruals. **Accrual Expense (Credit) Account** - The accrual expense account shows the expenses incurred but have not been billed to the payer. When you accrue the rebate amount, this account gets credited. When you reverse the journal entry, this account is debited. **Accrual Receivable (Debit) Account** - The accrual receivable account shows the amount of revenue earned that has not been received. When you accrue the rebate amount, this account gets debited. When you reverse the journal entry, this account is credited.
    
    -   When paying rebates, select an account for the accrual payable and accrual expense accounts: **Accrual Payable (Credit) Account**\- The accrual payable account shows what you still need to pay for bills and invoices that have been received. When you accrue the rebate amount, this account is credited. When you reverse the journal entry, this account is debited. **Accrual Expense (Debit) Account** - The accrual expense account shows the expenses incurred for which bills and invoices have not been received. When you accrue the rebate amount, this account gets debited. When you reverse the journal entry, this account is credited.
    
     |
    | **Customization** | **Custom Fields**\- This multi-select field lists all the custom transaction line fields you can use for rebate calculations. Only the custom fields for the currency are shown in this field. The custom field value can be sourced from an item record or any custom records. You can also manually enter a value on the transaction line while creating a transaction. Selected custom fields are displayed under the **Calculation Basis** field of the Agreement Details. You can also update the selection to add more or clear any previously selected custom fields. Any changes to the selection also reflects to the Agreement Details. |
    
3.  Click **Save** to finish setting the rebate preferences.
