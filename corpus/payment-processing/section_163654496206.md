The values in the Applicable Rebates window change if you modify any of these fields in a rebate agreement or agreement details record:

-   Stackable
    
-   Status
    
-   Payer
    
-   Payee
    
-   Calculation Method
    
-   Calculation Amount
    
-   Price Pass-through Type
    
-   Price Pass-through Value
    
-   Rebate Tiers
    

To edit a rebate agreement, go to Rebate Management > Rebate Agreements > Rebate Agreements and click **Edit** beside the rebate agreement that you want to edit.

Check the following guidelines when editing a rebate agreement:

**Agreement Start Date:**

You can change the agreement start date if there aren't any transactions linked to the rebate agreement.

**Agreement End Date:**

You can move the agreement end date to a current or a future date with or without transactions linked to the rebate agreement.

**Settlement Method:**

-   You need to specify a settlement method before generating a settlement.
    
-   When creating rebate agreements with auto claim and auto disburse settlement, you need to select a value for the settlement method and settlement frequency.
    

**Agreement Details:**

-   You can edit an unexpired agreement details record that is linked to transactions if the rebates are not yet claimed or disbursed.
    
-   You can remove the agreement details record if there are no transactions linked to the record.
    
-   The Agreement Details subtab always shows the latest version of an agreement detail. When you edit any field of that record, a new version of an agreement detail is created. The new version contains the updated values of the edited fields while the previous version contains the old values.
    
    On the transaction line, the Agreement Detail ID column shows the hyper-linked version number of the record. When you click the Agreement Detail ID, the **Version History** popup window appears showing versions of the agreement when the record was edited.
    
-   To add a new rebate agreement details record, see [Adding Agreement Details](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_163654409520.html).
    
-   You can't change agreement details for transactional or standard rebates to volume rebates. Similarly, after you set the agreement details to use volume rebates, you cannot change it to standard rebates.
    

**Rebate Tiers:**

-   If you change the minimum and maximum tier values while creating a transaction, the best deal selections in the Applicable Rebates window also change. For more information about best deals, see [Best Deal on Rebates](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_163654992232.html).
    
-   After you create and save a volume agreement details, you can no longer edit the customer and item criteria, and the accounting information. When you edit a volume agreement details, you can only update the values under the rebate tiers section.
    

**Status:**

The **RM Rebate Agreement Status Update** script runs daily at 12:00 AM to check and update the agreement status according to the scheduled start date and end date of the rebate agreement. The status changes either from Planned to Active, Active to Expired, or Expired to Complete.

| **From** | **To** | **Guidelines** |
| --- | --- | --- |
| Draft | Planned | 
-   The Agreement Start Date and End Date must be set to a future date.
-   The Agreement End Date cannot be earlier than the Agreement Start Date.

 |
| Draft | Active | 

-   The Agreement Start Date must occur on or before the current date.
-   The Agreement End Date cannot be earlier than the Agreement Start Date.
-   The Agreement End Date can be the same as the Agreement Start Date if the start date is a current date.

 |
| Planned | Active | 

-   The Agreement Start Date must occur on or before the current date.
-   The Agreement End Date cannot be earlier than the Agreement Start Date.

 |
| Planned | On Hold | The Agreement Start Date and End Date are not editable after switching the status to On Hold. |
| Active | Planned | 

-   The Agreement Start Date and End Date must be set to a future date.
-   The Agreement Start Date cannot be moved to a future date if transactions are linked to the rebate agreement.
-   The Agreement End Date cannot be earlier than the Agreement Start Date.

 |
| Active | On Hold | Changing the status from Active to On Hold disables the date fields. |
| Active | Expired | 

-   Editing the Agreement Start Date is not allowed.
-   The Agreement End Date must be set to a current date.

 |
| On Hold | Planned | 

-   The Agreement Start Date and End Date must be set to a future date.
-   The Agreement End Date cannot be earlier than the Agreement Start Date.
-   The start date can be moved to a future date if there are no rebate transactions linked to the rebate agreement.

 |
| On Hold | Active | 

-   The Agreement Start Date must occur on or before the current date.
-   The Agreement End Date cannot be earlier than the Agreement Start Date.
-   The Agreement End Date can be the same as the Agreement Start Date if the start date is a current date.

 |
| On Hold | Expired | 

-   Editing the Agreement Start Date is not allowed.
-   The Agreement End Date must be set to a current date.

 |
| Expired | \- | 

-   Rebate agreements expire after the Agreement End Date passes.
-   You can't edit expired rebate agreements.

 |
| Expired | Complete | 

-   The rebate agreement status switches to Complete automatically after all rebates are settled.
-   You can't edit rebate agreements with Complete status.
-   To renew a rebate program, create a new rebate agreement record and set a new validity period.

 |
