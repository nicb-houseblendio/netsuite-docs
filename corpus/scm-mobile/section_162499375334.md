This section provides troubleshooting guidelines and procedures for Mobile Printing, whether or not you use PrintNode integration. It covers the issues that you may encounter when Mobile Printing is set up incorrectly or if components and requirements are missing.

**ISSUE**: An error appears on the Print popup window, with the following message:

Unexpected error. Try again or, if possible, skip printing this document. If the issue persists, ask your administrator to contact NetSuite Customer Support.

To resolve this issue, verify that the following requirements are correctly set up:

1.  Your active API key from PrintNode is configured on your NetSuite account.
    
2.  At least one printer is available for your location.
    
3.  Your printers are mapped to the appropriate printer type.
    
4.  The report type associated with the label or document you want to print contains a default printer.
    
5.  The role has **Full** access level for the Documents and Files permission. Otherwise, when you view the execution log for the **customscript\_print\_rl\_trigger\_print** script, the following error message appears: The required parameter filePath is missing.
    

To review the list of requirements and procedures, see [SCM Mobile Printing](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161495837530.html).

**ISSUE**: On your PrintNode client, the state of a print job is set to **error**.

When you view the execution log for the **customscript\_print\_sl\_fileserver** script, the following error details appear: Invalid IPAddress.

To correct this error, add the correct IP address for the printer to the safelist on your NetSuite account. The IP address must match the one on your PrintNode client. For instructions, see [Configuring Security Settings](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161495993717.html).

**ISSUE**: When you configure and save your Mobile Printing settings, a BadRequest error appears in the job status.

To resolve this issue, make sure that you enter a valid URL in the one or both of the following fields: **PrintNode URL for View Printers API** and **PrintNode URL for Create Print Job API**. For more information, see [Configuring SCM Mobile App Settings](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161496866735.html).

**Issue**: When you configure your print security settings, one of the following error details appears in the job status:

-   Authentication error
    
-   API key not found
    

To avoid this issue, make sure that you enter your PrintNode API key after you add the IP addresses for the printers. For instructions, see [Configuring Security Settings](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161495993717.html).

**ISSUE**: Unable to print from your device because of the default **https://** text that appears in the **PrintNode URL for Create Print Job API** field on the Mobile -Settings page.

To resolve this issue, complete the following procedure:

1.  Using the Administrator role, go to Customization > Lists, Records, & Fields > Record Types.
    
2.  On the Record Types page, click **List** for the Print - Account Preference record.
    
3.  On the Print - Account Preference List, click **Edit** for the print\_api\_printjob key.
    
4.  On the Print - Account Preference page, in the **Value** field, delete the **https://** text.
    
5.  Click **Save**.
    

To verify that the text does not appear in the **PrintNode URL for Create Print Job API** field anymore, access the Mobile - Settings page. For instructions, see [Configuring SCM Mobile App Settings](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161496866735.html).

**ISSUE**: One or more printer records are inactivated automatically by a scheduled script from the SCM Mobile SuiteApp. For Ship Central, when you print a shipping label, this error message may appear: Error while submitting shipments.

This issue may apply to Ship Central and other mobile apps that support Mobile Printing. SCM Mobile doesn't use manually created printer records and inactivates them automatically through the scheduled script. It uses printer records that it automatically creates after you safelist IP addresses associated with your printers.

To avoid this issue, follow the procedures listed in this topic to safelist IP addresses and update, not create, printer records, [Mobile Printing Setup Procedures](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_161495837530.html#subsect_161495863496).

**ISSUE**: When you print or update printing settings, one of the following error messages appears:

-   That record does not exist. - This message appears when you tap the Print button.
    
-   An unexpected SuiteScript error has occurred. - This message appears when you select Print API Key Entry from the Printing submenu.
    
-   download HTTP response status code 500 - This message appears when you select Audit Logs from the Printing submenu.
    

To avoid this issue, make sure that you have enabled the Online Forms feature and configured the Online Form User role. For instructions, see [Setting Up the Online Form User Role](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0814113835.html).
