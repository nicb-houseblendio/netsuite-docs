You can trigger a cache invalidation request for more than one domain at the same time. You can also choose to invalidate the cache for the whole domain or for specific URLs.

**Clearing Cache for the Whole Domain** - As you develop your Commerce web store, you might need to redeploy SSP applications. To see changes to the content delivered from the file cabinet, script files, CMS, and Item Search API request output, use the Clear Cache for the Whole Domain option.

You can also choose this option if you've made several changes and don't remember all the URLs.

**Clearing Cache for Specified URLs** - Most content is cached in SSP and SuiteScript method calls. To target specific SSP or SuiteScript files that contain the definition of the content you want to clear from the cache, use the Clear Cache for Specified URLs option.

For example, suppose you have a banner on your website that you plan to change frequently. Every time you want to update it, submit a cache invalidation request using the URL of the SSP file (`/page.ss`) that defines the banner on your site.

#### To create a new cache invalidation request:

1.  Go to _Commerce > Content Management > Cache Invalidation Requests > New_.
    
    The New Invalidation Request dialog opens.
    
    Note:
    
    You can also open the New Invalidation Request dialog from the Cache Invalidation Status page by clicking **New Invalidation Request**.
    
2.  From the **Available Domains** list, select one or more domains for which you want to invalidate the cache. You must select at least one domain before you continue.
    
    Use the controls to move domains between the **Available Domains** box and the **Selected Domains** box.
    
    Note:
    
    Commerce domains with or without CDN are listed under Available Domains if they're in the Live state.
    
3.  Choose the type of operation you want to perform on the selected domains:
    
    -   **Clear cache for the whole domain(s)** - Clears cache for the whole domain.
        
    -   **Clear cache for the following path(s)** - Clears cache for the specified URLs. If you select the **Clear cache for the following path(s)** option, you must add at least one URL path before you click Submit.
        
    
    Note:
    
    For information about determining which URL you should use in cache invalidation requests, see [Find URLs for Cache Invalidation](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_4350174748.html).
    
4.  Click **Submit**.
    
    Note:
    
    For Commerce domains without CDN caches, only internal caches are cleared by the cache invalidation request.
