Note:

The procedure for creating, installing, and linking an SSP application to your website differs based on whether the SSP application is written in SuiteScript 1.0 or SuiteScript 2.0. If you are using an SSP application written in SuiteScript 1.0, see section [SuiteScript 1.0 SSP Applications](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1529595280.html).

To build a SuiteScript 2.0 SSP application:

1.  Turn on the required features in NetSuite.
    
    All features required for SuiteScript 1.0 SSP applications must be enabled before SuiteScript 2.0 SSP applications can be enabled. See [Enable Required Features for SuiteScript 1.0 SSP Applications](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2492346.html).
    
2.  Write the SuiteScripts that will implement your web store customization, including .ssp files to render the UI and .ss files to handle requests. For examples, see [Sample SSP Application Code (SuiteScript 2.0)](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1529598972.html).
    
3.  Create and assemble other assets needed for your SSP application.
    
4.  Create an SSP Application record in NetSuite. See [Create a SuiteScript 2.0 SSP Application Record](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1529598216.html).
    
5.  Upload your SuiteScripts and other required assets to the file cabinet folder listed in the SSP Application record. See [Upload SSP Application Files to the File Cabinet](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1529598265.html).
    
6.  On the SSP Application record, select the default SSP file that defines how the SSP application will integrate with the web store. See [Select Default SSP File](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1529598336.html).
    
7.  Deploy the SSP application to a website or a domain in your NetSuite account. If you deploy to a website, the SSP application is available on all domains associated with that website. If you deploy to a domain, the SSP application is available only on that domain. If an SSP application already exists at your chosen URL root, you will need to undeploy the existing application before you can deploy the new application. See [Deploy and Undeploy SSP Applications](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1529598384.html).
    

## Debug and Bundle an SSP Application {#subsect_1529949487}

After you have created an SSP application, you can:

-   Debug your web store customization by running your SuiteScripts and reviewing entries in the Script Execution Log on the SSP Application record. See [Debug a SuiteScript 2.0 SSP Application](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_1533377350.html).
    
-   Use SuiteBundler to package your web store customization for installation in another NetSuite account. See [Bundle an SSP Application](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_N2495338.html).
